# 游戏测试指南

本指南说明怎样测试 sgstory-books 的故事网页，并留下别人能复现的反馈。它不要求试玩者懂代码，也不把自动化脚本当成人类体验的替代品。

## 阅读路线

| 你要做什么 | 只需阅读 |
|---|---|
| 人类手工试玩、反馈体验 | [共同约定](#共同约定)、[人类测试人员](#人类测试人员)、[报告与交付](#报告与交付) |
| bot 操作浏览器、做回归并留证 | [共同约定](#共同约定)、[bot 测试人员](#bot-测试人员)、[报告与交付](#报告与交付) |

故事的具体玩法见对应的 README 或试玩清单。例如[《巴别之井》试玩清单](../../stories/babel/PLAYTEST.md)提供场景问题，但其中的玩法、死亡规则和标签可能属于旧版；先对齐本次版本，不照抄旧规则。现成脚本见[工具索引](../../tools/README.md)。

## 共同约定

### 先说清测试的是哪一版、哪一种测试

| 类型 | 要回答的问题 | 不能据此宣称 |
|---|---|---|
| 试玩 | 正常玩家能否操作、看懂、继续；哪里不好玩 | 全部功能通过、已经通关或可以发布 |
| 缺陷回归 | 已知问题在指定修复版是否消失；相关正常路径是否仍成立 | 同一修复覆盖所有场景或所有浏览器 |
| 受控自动化 | 在指定夹具、随机流和断言下，逻辑或接线是否成立 | 玩家自然到达该状态，或真实布局已验收 |
| 发布验收 | 当期发布票要求的前置、清单、平台和阻塞项是否全部核过 | 用一次试玩或几个脚本代替完整发布门 |

开始前记录故事、URL 或 HTML 文件名、测试时间、页面显示的版本、浏览器和设备。缺少的信息写「未知」或「未显示」，不要猜。bot 另需固定故事提交、引擎 pin 与实际加载产物，见自己的章节。

网页部署、本地构建和仓库最新源码可能是三种不同对象。旧报告只说明旧版本；复查修复须重新确认测试对象。需求或玩法说明互相冲突时，记「规则待确认」，向任务发起者确认后再判，不凭印象补预期。

### 保住自己的存档，保持正常玩家路径

- 使用独立浏览器用户配置，或不与其他活动共享的专用隐私会话，只操作本轮测试档。普通新窗口仍可能共享原配置的站点数据，不算隔离；隐私窗口通常不保留关闭后的数据。需要长期保留时，先使用游戏提供的导出功能（若有）。
- 覆盖档、重开、刷新、清档或导入前，先记录现场；不要清除个人浏览器的全部站点数据，也不要导入别人的私有存档。
- 试玩通过页面上的正常按钮、鼠标、键盘或触控进行。不改角色数值、不送装备、不跳剧情，不注入通关。
- 为回归而摆状态、固定随机数或直接调用保存接口可以作为受控测试，但要单列说明。这些操作不能冒充正常试玩，也不能代替对应的界面点击验证。

### 观察一条完整链，而不只是「按钮点了」

每个场景按「**操作前状态、操作、反馈与结算、下一步**」检查。例如使用道具，不仅看提示，还要看数量/耐久、体力/效果、背包刷新和继续操作是否一致。

区分以下几类：实际行为违背规则的功能缺陷；字小、难点、术语不明的体验建议；字体缺失、浏览器启动失败的环境问题；脚本选错按钮、等待超时的驱动问题；明确披露的设计边界。暂不能定性的写清疑点，不统称为 bug。

## 人类测试人员

本章不需要安装 Node、配置自动化工具或阅读脚本。准备约 20 分钟即可做一轮有用的试玩；未走完也可以交反馈，不必为了「通关」反复耗尽时间。

### 1. 打开与记录

打开任务给的网页或 HTML 文件；没有指定测试版本时，先询问要测线上版还是候选文件。[在线站点](https://sagitrs.github.io/sgstory-books/)不是固定的历史版本，测试时仍要记录日期和页面版本。

记下浏览器、电脑/手机、版本文字。留一张开场截图。中文显示成方框时，先换一个已有中文字体的浏览器环境；仍不正常就保留截图，注明环境和现象，原因未明时不要直接归咎于故事，也不靠猜测阅读。

### 2. 用正常玩法走一轮

先玩一小段，再按下面挑选能到达的场景。故事没有某项机制就记「不适用」，没到达则记「未测」及原因；任务清单要求的功能缺失要报不符，不能写不适用。

| 场景 | 怎么试 | 观察什么 |
|---|---|---|
| 开场与导航 | 开始游戏，进入下一地点，再试允许的回程 | 位置与正文一致，出口可理解，没有无提示死路 |
| 采集、宝箱、装备、道具 | 各做一次可用动作；再试一个明确不满足条件的动作 | 奖励及时可见；数量与耐久不混淆；被拒时有理由且不偷扣资源 |
| 普通战斗 | 打一场，留意每回合和结束后的状态 | 玩家、敌情、伤口、掉落与正文一致；结束后有可用的下一步 |
| 恢复或整备 | 受伤时恢复一次；条件允许时再试满状态 | 预计效果、实际变化、成本及可重复性符合本版规则 |
| 保存与恢复 | 按下一小节做 | 恢复的事实与界面一致，不静默覆盖普通档 |
| 死亡与重开 | 正常遇到失败时，试页面提供的读档/重开入口 | 按本版规则结束和恢复；原战斗按钮不残留、不重复结算 |

敌情未知、某动作隐藏或失败，不一定是缺陷。先看提示、工具条件和故事规则；实在看不懂，「不知道为什么不能做」本身就是有效的体验反馈。

### 3. 把存读档单独做一次对照

1. 在本版允许保存的安全场景，记下位置、体力、伤口、装备、背包和当前行动，保存到明确可用的普通槽。
2. 做一个能看出变化的动作，例如换地点或消耗一件道具，然后读回刚才的档。
3. 对照保存时的记录：事实恢复了吗？正文、敌情、按钮和背包也对上了吗？只出现「读取成功」提示不算核完。
4. 游戏有快存或保底档时，记录其名字与显示槽号；核对系统写档不会无提示损坏普通档。只用测试档做覆盖实验，不凭记忆假定某槽是普通槽。
5. 在本版禁止保存的场景，检查故事入口与侧栏入口是否都拒绝；在允许保存的场景，检查普通保存仍能成功。不要绕开按钮强行存。
6. 把刷新页面另列一次：刷新前截图，刷新后记录实际恢复到哪里，再与该版的继续/自动恢复约定比。刷新恢复与手动读档不是同一项。

### 4. 看一遍阅读与操作体验

- 桌面阅读：下一段出现时能看见吗？回看旧文本时会被拉回底部吗？背包、状态或通知刷新后，阅读位置与展开状态是否丢失？
- 手机阅读：有无横向溢出、被遮挡的行动、太小的文字或难点的道具名？若只有电脑，可缩窄窗口，但报告要写「窄窗口」，不能写「手机实测」。
- 键盘与放大：试 Tab、Enter/Escape 和浏览器 200% 放大。看焦点能否找到，弹窗关闭后能否继续操作，核心行动是否仍可达。
- 把「不好玩」说具体：哪一步最想跳过、哪句话不懂、需要点多少次。不同故事不必都有 MP（魔力）栏；只核它声明提供的资源，不把缺 MP 自动判成缺陷。

### 5. 遇到问题，先留现场再重试

截图，抄下操作前后状态，用最短步骤描述预期和实际。条件允许时从同一个测试档再做一次，并记录两次结果；随机结果不同时如实写。

不要为了让流程走完而改存档或换掉证据。卡住就结束本场景，标明后续未覆盖。头目连续失败可以反馈难度，但几次失败不能证明游戏不可能通关，也不是胜率统计。

使用[报告模板](#报告与交付)提交即可。控制台日志是可选补充，不懂控制台也能提交有效反馈。

## bot 测试人员

本章把浏览器实测与脚本回归分开。先完成环境和版本守卫，再操作；只有读取源码或下载 HTML，不能称为网页试玩。

### 1. 固定对象，准备隔离环境

- 记录任务授权、模式、预算/停止条件和目标。源码测试记录完整故事提交及[引擎声明件](../../.github/engine-ref.json)的 `ref`，检查引擎检出 HEAD 与它一致；不要擅用引擎 main，也不要自行改 pin。记录两棵工作树的源码状态，有未提交改动须附差异或摘要，不能仅用 HEAD 冒充实际代码。
- 本地构建记录构建命令、版本参数与 HTML 的 SHA-256。在线测试记录最终 URL、时间、版本文字，保存实际加载的初始 HTML/响应及其摘要；只对另一次下载做摘要，不能证明它就是浏览器加载的内容。确认不了故事提交时明记未知。
- 复用已有可用的真实浏览器工具，例如浏览器交互工具、Chrome DevTools Protocol（CDP）、Playwright 或 Puppeteer。缺浏览器时标「环境阻塞」，不能用 jsdom 截图或源码推断补齐。
- 使用专用 browser context 或新 profile，不复用个人 Cookie/存档。调试连接只在本机可达，记录自己创建的进程与目录。缺依赖须报告，不擅装系统软件，不杀共享浏览器或 CI。
- 在舰队共享主机，临时目录放 `~/tmp`，遵守低载窗与任务预算；构建、依赖安装或全量回归须核任务授权，不随意扩大一次试玩的范围。

开始后先确认正文可读、正确的开场和版本确实出现。若发生字体或 GPU/浏览器故障，保留失败轮，再在修正后的环境重做；不能把装置问题算成产品缺陷。

### 2. 用界面动作推进，用只读观察核验

按共同约定的完整链测试，至少安排正常探索、道具/装备、普通战斗、存读档与阅读操作。具体覆盖由任务清单决定，不照搬某次试玩到达的层数。

1. 先读取当前屏幕、可见文本与控件，确定目标按钮的标签、作用域、可见和可用状态。存档弹窗、空槽/占用槽会改变按钮，不硬套旧选择器。
2. 经浏览器发真实鼠标/键盘/触控操作。直接 `Save.slots.save()`、`Engine.play()`、DOM `.click()` 或写 `State.variables` 属脚本/API 或夹具路径，要单列；不能据此认定玩家点击入口已验。
3. 等待本次动作的语义结果，例如地点改变、当前选择出现、结算文本及背包同步。不只等页面加载完，也不把固定睡眠或某个生命周期事件当作全部异步输出结束。为动作设超时；超时先保留现场并查驱动。
4. 观察尽量取 DOM 和经源码确认的只读状态。不调用会初始化、刷新、领奖、推进时钟或消耗随机数的函数来「读取」状态；缺读数写未知，不伪装为零。
5. 对照事实与呈现：位置、体力、伤口、装备/数量/耐久、战斗阶段/敌情、当前行动。校验时遵守未知敌情的披露规则，不要求界面暴露隐藏信息。

存档检查要覆盖允许/禁止两个场景、故事/侧栏两个入口，以及普通/系统档的区分。记录 API 索引与玩家显示槽号的对应关系，从该版的故事配置或槽语义读，不硬编码旧的 `[3,4]`。换号时应核新系统槽受保护、旧槽按新规则恢复普通使用，且系统自己的写档仍成功。

导航、读档、重开后核对正文和可用行动是否属于当前状态；战斗结果、掉落或回调是否被旧界面再次触发。刷新恢复另设用例，不拿手动读档通过替代。

### 3. 布局、触控与随机性单独记账

- 用真实浏览器覆盖桌面与窄屏，可选 1440×1000、390×844，必要时加 320 宽、200% 放大、键盘与弹窗焦点。报告同时记录 viewport、缩放及触控设置。
- 图像要实际检查字形、遮挡和视觉可读性；DOM 有文字、控件有尺寸，不证明玩家能看见或点中。滚动需记录动作前后位置及回看场景，不只截一张最终图。
- CDP/浏览器模拟触控要确实发触控事件，并检查响应；它仍是「模拟触控」，不是手机真机。resize 不是触控验收；键盘与读屏也不能从鼠标点击推断。
- 记录装备、初始状态、策略、尝试次数；受控随机序列另记来源与耗尽行为。不同随机结果不做逐字节相等断言，也不反复换样本直到全绿。胜率由适用的跑分器与样本口径核，不由少量 UI 战斗推断。

### 4. 留证、重试与清理

每个用例给唯一编号，保存时间、操作序列、期望/实际、前后截图与状态。日志保留原始顺序；建议截图旁放同名 JSON，便于关联场景、状态与动作。

收集控制台、未捕获异常、网络失败和驱动日志。分别定性：可读的动作拒绝不一定是未捕获异常，favicon 404 不等于故事不可用。协议重连可能重放旧日志，去重须能识别同一事件，并保留原始数据，不能仅按相同文本删掉多次真实错误。

选择器不存在、超时、驱动解析错误，要留失败轮与原因，再用新的轮次编号修正重跑。失败日志不覆盖，也不并入产品缺陷计数。每条结果用「通过／不符／环境或驱动阻塞／未测／不适用」，不将退出码零、零断言或诊断报告态当成全项通过。

结束时只关闭自建 context/进程，记录是否保留本轮测试档与临时目录。报告、关键原始输出和必要脚本归档；公开 ZIP 排除 profile、Cookie、Token、私钥和未经授权的用户存档。清理、重连与保留状态也写入报告。

### 5. 现成脚本是补充，不是浏览器替身

| 入口 | 能支持的结论 | 不能替代的部分 |
|---|---|---|
| [场景链](../../tests/scenario/run.mjs)、[装配自检](../../stories/babel/verify.mjs)、[引用核](../../tools/check-refs.mjs) | 各自声明并实际触发的逻辑、装配或引用检查 | 全剧情、真实布局、阅读与触控 |
| [e2e-harness](../../tools/e2e-harness.mjs)、[e2e-drive](../../tools/e2e-drive.mjs) | 当前实现使用 jsdom，能做脚本 DOM/保存/接线回归；部分场景直铺状态 | 真实浏览器启动、整页重载、滚动尺寸、字形或设备体验 |
| [balance-babel](../../tools/balance-babel.mjs) | 指定引擎、夹具、策略与随机流下的战斗统计 | 正常旅程到达、界面按钮、玩家理解与完整发布门 |

工具名字或索引中的「真 DOM」不是布局验收证据；以实际运行器和覆盖面为准。用例中的待判/未机械判项须逐条保留，不能合并进绿。[夜窗流程](../../.github/workflows/e2e-window.yml)会调用这些 jsdom 驱动，但它不是逐 PR 门，也不等于真实浏览器布局验收。

从本仓根运行已有脚本的示例（按工作流准备 Node 22/Python 3；`ENGINE` 须先设为匹配本仓 pin 的独立引擎检出绝对路径）：

```bash
set -euo pipefail
: "${ENGINE:?先设置按本仓 pin 检出的独立引擎目录}"
node tools/check-engine-pin.mjs --engine "$ENGINE"
node stories/babel/verify.mjs --engine "$ENGINE"
node tools/check-refs.mjs --engine "$ENGINE"
node tools/e2e-harness.mjs --engine "$ENGINE"
node tools/e2e-drive.mjs --engine "$ENGINE"
```

逐条保留读数与退出码；示例遇失败即停，后续命令记未执行，不只看最后一次返回码。首条是[pin 自证](../../tools/check-engine-pin.mjs)，不符就先修环境。这些命令不是完整测试流程，也不自动构建新产物。先按[巴别工作流](../../.github/workflows/babel-tests.yml)的步序核 pin、构建和版本参数；故事目录及 HTML 输出使用绝对路径，引擎构建也可能生成引擎侧测试 bundle，因此只在独立可写检出执行。jsdom 按现实现从引擎树解析，依赖准备见夜窗流程；缺它须明记阻塞，不在 books 私加依赖。各工具的参数、自检、期望与退出码见[工具源码头注](../../tools/e2e-harness.mjs)及[工具索引](../../tools/README.md)，计数不能照抄旧值。

发布验收另按当期发布票执行。例如[0.0.2 质量门 #197](https://github.com/sagitrs/sgstory-books/issues/197)规定前置与完整清单；本文不重写那份权威清单，也不把旧票里别席 home 目录当成可随意进入的共享工具入口。工具不可达时申请可用副本并记录来源，不能越界或标绿。

## 报告与交付

### 可复制模板

人类只需写文字和截图；bot 在相同模板下补提交、pin、产物摘要、命令/驱动、原始日志及结构化读数。

```markdown
# <故事> · <试玩 / 回归 / 受控自动化 / 发布验收> 报告

## 对象与环境
- 时间、URL/HTML、页面版本：
```
