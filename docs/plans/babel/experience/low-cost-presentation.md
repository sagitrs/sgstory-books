# 地点、身份与行动结果的低成本呈现

需求：[books #473](https://github.com/sagitrs/sgstory-books/issues/473)。批准状态与原文见[裁定与来源](decisions-and-sources.md)。这是表现层设计，不是实现或验收报告。

## 1. 目标与取舍

用少量、有用途的视觉锚点和清楚反馈，帮助玩家理解当前地点、交互身份、可选行动及其真实后果。图片承担定位、辨认或阅读节奏，不只做壁纸。选择与后果仍是继续游玩的主体。

投入顺序建议为：先可靠，再清楚，再有画面，最后扩规模。美术草案可并行，但不能遮住战斗或保存的断口；本设计不判定已有缺陷当前仍存在，也不以画面改进代替修复验收。

“低成本”包含素材制作、授权、集成、校对、响应式、资源管理和长期维护。本轮没有报价、工期或留存实验，不承诺静态图片免费、修改只需几行样式，或美术必然提升留存。

## 2. 同一套阅读骨架

建议把当前故事、操作和刚发生的结果放在一起，历史与规则帮助另放：

```text
地点名／眼下目标
场景画框（窄屏短横幅，可收起）
当前情境：现在正在发生什么
世界内唯一身份＋一句话（交互时才显示身份肖像）
行动：做什么；已知条件、代价或风险
行动结果：真实原因；实际得失
历史回顾／机制帮助（可展开）
```

这是信息组织，不要求建立新任务、对话或状态引擎。“眼下目标”引用既有目标或当前处境，玩家可以不接受；不为了介绍玩法强迫教学、接任务或成交。

桌面优先图文分区；窄屏优先连续阅读、小肖像和短横幅。正文使用稳定、对比清楚的底色，不默认压在复杂全屏背景上。字号、段距、行宽、图片高度与触屏目标尺寸在小样中比较后再定，不照搬英文截图的三栏与字宽。

## 3. 地点图

### 少量主体，明确地点

第一轮地点候选是共炉、工坊、河岸：公共火堆、工具台与渡口芦苇应有不同主体，不是同一张图只换颜色。具体图与节点映射尚待确认，不把这些例子登记成新地点。

先审阅[既有七名河图稿目录](../optional/tutorial-seven-names/README.md)，确认质量、语义和授权后再复用。文档有图不等于图已经在线上使用，也不默认每节点重新制作。河域底景可以复用，裁切或事件主体体现差异；地点名与当前情境仍明确出现，不能让图代替事实。

场景插图与路线地图分工：插图建立处境，地图说明连接。图中的门、船或道路不是新出口，不自动可点击。昼夜、天气、损毁等图像变体暂不做；以后必须先有相应真实事实。

### 图跟随真实状态

从已有地点与场景事实选择图片，不另存可独立修改的“图片地点”或“已到达”进度。选择被拒绝、战斗未交接、结果缺失、刷新或载入恢复时，不提前切成成功场景。

图片先有固定占位，正文和按钮先可读，不等待整套图片加载。可关闭装饰图；图片缺失、慢网、解码失败时保留地点名、情境和全部原有功能。装饰图不让读屏器反复朗读，承载重要信息的图仍有文字等价说明。

## 4. NPC唯一身份与模板立绘

**设定集保留人物细节；游戏内模板化、身份化，用世界内唯一身份代替姓名。** 这不是取消真实人物，也不是把角色改成虚拟人。人物的背景、关系和世界事实依旧存在，玩家无需先记专名才能知道找谁做什么。

### 显示规则

- 身份称谓是默认显示，不默认“姓名＋称号”双标签，也不另给人物编号让玩家背。
- 同一世界有相同职能时，以地点或职责消歧。必须能唯一指向当前交互对象，不能两个不同人物都只显示“工匠”。
- 示例“工坊铸匠”“灯下医者”“渡口守绳人”只说明称谓结构，不是新人物、职位或地点定稿。实际称谓依现有设定校对；菜单、正文、结果和历史中的称谓一致。
- 内部实体ID、交易资格、物品所属、关系事实和保存身份仍各归原业务实体。显示改名不授权替换ID、重写旧档或合并不同NPC。
- 此约束用于NPC呈现，不借机修改玩家、同伴或敌人的身份规则。

### 复用规则

第一轮从两个已有、适合多次接触的身份试起。工匠与医者是职能示例，是否采用及其具体人物均待确认。

同类可以复用半身肖像、交互结构和简短说话模板；按已有世界主题作必要变化，不要求每个实例专属图。画像不能擅定年龄、性别、文化背景，也不能把偶然生成的细节变成设定事实。

身份有声音，但不增加姓名负担。例如医者关注伤势，铸匠关注工具状况；实际拒绝、成交、受伤返回可获得一句回应。回应只读既有事实，不新增人物任务、好感度、长期关系账或无事实的熟识台词。

模板表达立场后，仍清楚列出资格条件与下一步。改表达，不改门槛、价格、奖励或交易接口。

有限色彩、剪影、版画感或克制线稿均可比较，先统一轮廓、服装语义与笔触；不混用彼此冲突的城镇、人物和水灵画风。暂不做表情包、口型、全身动作、动态立绘或配音。

## 5. 与画面一起整理的反馈

| 项目 | 呈现要求 | 不改变什么 |
|---|---|---|
| 当前故事与历史分区 | 当前地点、事件和操作稳定可见；通知筛选不筛掉正文 | 不删除事件事实，不重建进度账 |
| 就地行动结果 | 显示真实成功／拒绝原因和实际得失，不只藏在历史日志 | 未提交不播成功；取消、拒绝、重复不造半提交 |
| 地点与眼下目标 | 给一个已有的当前处境或目标，帮助理解下一步 | 不新建任务或强制教学，不要求接受目标 |
| 旅途小结 | 简短呈现真实路线／事件、所得、返程代价和接下来可做什么 | 不新增奖励、成就或全胜条件 |
| 保存与恢复反馈 | 说明实际保存位置，并提供符合现行保存规则的可达恢复入口 | 不只美化“保存成功”，不擅自解除保留槽限制或改旧档 |
| 文案与机制帮助 | 中文主名、短行动按钮，详细规则可展开且可达 | 不靠删条件、代价或暂定标记制造轻松 |
| 库存语义 | 件数、使用次数、货币名称与数量分开写 | 不借标签修改物品载荷或币制 |
| 长文与低图模式 | 比较字号、段距和触屏可用性，关图后仍能完整行动 | 不以强制动画或逐字打印拖延选项 |

### 旅途小结只呈现已发生的事实

成功提交返城后，展示既有来源可核的路线／事件、实际获得物、损毁或变脆弱项和合法后续活动。缺事实的项不编造；没有遭遇不能写成已战胜，没有损毁标记不能断言没有损毁。

提前返城与完成分开；只有七名河E9成功返程提交完成。本层机会、E9、旧付费卷轴沿各自既定结算，小结不能把付费卷轴写成完成或脆弱结算。若先提供预览，明确标成预计项；真实提交后才写实际项。

小结读取已有提交结果，不因打开、刷新、折叠或载入重奖、重结算、重掷骰，也不另存可自由编辑的“已完成／已处理”账。失败与交接缺失应明确反馈，不能靠图片、台词或小结补成成功。

[七名河导航终裁](https://github.com/sagitrs/sgstory-books/issues/397#issuecomment-6034021342)保持不变：未处理不继续，真实胜利及唯一结算或既有属性脱离成功才放行；不是强制全胜。合法非战中早返仍独立，E8冠交付与原13边／六路线不改。

## 6. 最小小样与观察

这是一项后续验证建议，不是已实施内容，也不批准测试工具或改变正式验收。

- 内容范围：L10的一小段访问，加七名河的一段既有正常路线；具体身份、节点与路线在实施前确认。不用首页战斗教学代替所选片段。
- 美术上限：3张地点图＋2张身份肖像模板，已有图计入上限。先核可复用素材，不预建全20世界、全部建筑或逐人专属肖像。
- A层：阅读与反馈整理后的纯文字；B层：A加地点图；C层：B加身份肖像。三层使用相同内容、功能与身份称谓。
- 比较安排：控制重复游玩熟悉度，尽量平衡顺序或分组；若C同时修改人物文案，只能评价整套人物呈现，不能把变化单独归因于立绘。
- 探索性读者：例如6–10名目标读者。记录能否识别地点／目标、辨认身份／职能、解释选择与结果，以及大图滚动、卡点与继续意愿，不只问美观。

产品检查与体验观察分列。后续正式产品检查须覆盖窄屏、键盘／回焦、关图／失败回退、读屏文字等价，以及拒绝、取消、真实提交、刷新、载入与迟到回调不会改变业务事实；不能凭截图或DOM相等推定后台正确。受测候选、完整pin、产物、路径、通过／失败／未覆盖须具名记录。

6–10人的方向观察不是统计有效的留存实验，不替代功能、兼容、保存或正式D/T验收。本次没有招募、试验、性能读数或新版复测。

## 7. 素材治理与非目标

每份候选素材应登记用途、所映射的既有地点／身份、作者或来源、许可及可修改范围、尺寸／格式／体积、版本和文字回退。先人工校对世界语义、称谓消歧、画风及必要裁切，确认后才作为产品资产。

官方竞品图片只作研究引用，不复制入游戏。生成式工具可以辅助构图与草案，但须核工具、参考素材和输出的使用条件；统一画像、修改、裁切与维护仍有成本。本次不声称已完成商用授权尽调，也不下载竞品图进仓。

不做三维地图、实时天气、全20世界资产、所有NPC专属图、新人物关系系统、配音或强制转场。不改变价格、检定、战斗、奖励、导航、返程、存档或引擎pin。不指定版本与实施席位；[0.0.3边界](../optional/tutorial-seven-names/v0.0.3-boundary.md)不追加本设计。
