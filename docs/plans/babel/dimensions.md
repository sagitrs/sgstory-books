# 复杂度维度框架

> 战斗系统沿层递增复杂度，但**先定维度（轴），再定内容**：内容即"段 × 轴"的取值组合。本框架供 sgstory#1728 伞及其五张子伞（#1729–#1733）引用——子伞按"查本表取值 → 生成内容清单 → 无原语支撑的取值即引擎缺口"工作。所录为策划口径下的设计参考，不构成约束或建议。

## 三条原则

1. **维度先于内容**：先定轴、再填值；新增内容必须能落到某轴某段，否则不进本作。
2. **复杂度＝激活的取值数**：每段在诸轴上解锁新取值；旧取值默认保留继承（各轴注记例外）。
3. **一段是全集的种子**：所有轴在一段就存在（哪怕只有一个朴素取值），避免中途凭空出现全新系统。

> **段位口径**：全井只有**四段文明**（第 10／20／30／40 层大空洞各领一段）。第 41–49 层是**终程**——登天攀爬，无空洞、无文明；第 50 层即**结局**，不属于任何段。下表诸轴的"终程"行即 41–49 层的取值。

## 主维度（十轴）

### 一、装备部位（slots）

| 段 | 取值（新增／激活） |
|---|---|
| 一段 1–10 | 武器；随身（腰间／背带） |
| 二段 11–20 | ＋护甲（躯干）、盾位、饰物 |
| 三段 21–30 | ＋头（盔／护目／防毒）、弹药与背具 |
| 四段 31–40 | 义体位（义眼、义肢、神经接口、皮下植入）——可与原生护甲位互斥或叠加，由规则包定 |
| 终程 41–49 | 整体密封甲位、生命维持位、反重力器件位 |

引擎衔接：**无「槽位注册面」** —— 实测 `slotRegistry|SLOT_TIERS` 在 `src/**` **0 命中**；`Item.slot` 是**自由字符串**、`RPG.slotLabels` 只是可选显示名 ⇒ **加新槽＝纯数据**（零引擎改）。现仓实取槽位：`weapon`／`body`／`feet`／`shield`／`shoulders`／`belt`／`vest`／`arms`／`mount`（后六个已由 `#1779` 的二段装备扩展落地）。⇒ 本轴的新增位是**内容面**，不是原语面。

### 五、Debuff 种类

自然（流血、骨折、自然毒）→ 奇幻（恐惧、中毒、魅惑、疾病）→ 现代（燃烧、休克、压制）→ 赛博（EMP、系统锁定、纳米中毒）→ 环境（真空暴露、失压、缺氧）。

### 六、影响时间（duration 语义）

即时 → 场景内 → 回合级＋豁免结尾（saveEnd）→ 层数递进（exhaustion 式）→ 消耗依赖（生命维持耗尽即危）。

引擎衔接：五、六两轴即 `#1689` 条件系统的内容面——种类梯度＝条件条目的分期，时间梯度＝duration 原语的分期。**现状（实测）**：`#1689` 是**设计稿**，其 P1 已落地（`#1741`／`#1758`：`Conditions` 15 条声明表 ＋ `scope` 两档 ＋ `saveEnd`／`turn` 计数 ＋ 死亡清档，见 `src/dnd/dnd-5e/core/conditions.js`）；**P2–P4 仍为规划**（未落地）；第五档「通用消耗存量」的设计已定稿（`#1759`／`#1771`，落 `#1689` §十，定义 `DND5E.Environment`），**实现串行于后**。⇒ 前四级**部分**可用（P1 面），第五级是新增面，恰是终程真空环境的刚需。

|---|---|

| 二段 | 祭坛／泉水、商队馈赠（建议项） |
| 三段 | 废弃实验室、充电站 |

引擎衔接：这是"随机换卡"的内容池本体——RPG.rng（#1710 已闭环）负责抽卡，encounter／loot table 为缺口（伞 #1728 伞面第 2 项）；NPC 小队的出现依赖"同场攀登者／空洞居民"两项留白（见 outline 设定留白与 layers 本表前提）。

### 十、建筑与设施（每层常驻）

每层都有建筑物，提供常驻服务；形态随段演进：

| 段 | 取值 |
|---|---|
| 一段 | 交易市场与商店（食物、草药、武器、装备）；治疗所 |
| 二段 | 铁匠铺、行会工坊、旅店（酒馆）；神庙医疗（建议项） |
| 三段 | 医院；保镖公司；军队（征兵处）；研究室 |
| 四段 | 义体诊所、黑市、巨企服务点（建议项） |
| 终程 | 气闸补给站、休眠舱（建议项） |

与「每层主体种类」的关系：建筑是层的**常驻设施**，与随机主体并行——层的随机主体（遭遇）之外，建筑提供可反复使用的服务入口；是否把"某类建筑"本身列为随机主体之一，由玩法侧定。

引擎衔接：**引擎现无建筑／设施面**——常驻服务实体（买卖、治疗、招募、委托）与场景的挂接缺失；与伞 #1728 伞面第 3 项（建设面）、第 6 项（大空洞社交区·NPC 服务面）同族，建议并入伞面公共能力（建筑／设施原语）。与队友形态轴直接互为入口：旅店（二段）即"酒馆组队"之处，军队（三段）即"应召入伍"之处。

## 用法（子伞工作流）

1. 查本表：取本段在诸轴上的取值集合；
2. 内容清单＝取值 × 具体条目（怪物、道具、装备逐条落实）；
3. 引擎缺口＝取值中无原语支撑者（对照 sgstory#1728 伞面六项与在册票）。
