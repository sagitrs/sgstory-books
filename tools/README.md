## 退出码三分：`0`／`1`／`2` 各指什么（★读任何读数前先看这一节）

本目录各工具一律**三分**退出码。★`1` 只表示「**判据红**」，✗ **不**表示「装置错」——
装置错（引擎树 ≠ 声明 pin／缺依赖／缺产物／清单读不出…）一律 `2`，且**具名**写出真因与修法。

| 码 | 含义 | 何时出现 | 处置 |
|---|---|---|---|
| `0` | 判据绿（须带读数，✗ 不是「通过」二字） | 各面如期 | 记读数 ✓ |
| `1` | ★**判据红** | 实现与判据不符 | 修实现；✗ 别改判据迁就实现 |
| `2` | ★**装置错**（✗ 不当判据红） | 引擎树 ≠ 声明 pin ｜ 缺依赖 ｜ 缺产物 ｜ 清单读不出 | 修装置（指向 pin 树／补依赖／重建产物） |

★这条是从一次**误报**里来的（`books#295` 勘察 ⇒ `books#297` 修法，`tools/check-refs-docs.knives.sh`）：
该刀架的末刀断言「复原后 rc=0」，而它只在**引擎树 == 声明 pin** 时成立 ⇒ 换引擎树跑 ⇒ 末刀红 ⇒
旧形把**装置错读成了判据红**（`rc=1`）✗。现加 **pin 前置自证**（调 `check-engine-pin.mjs`）⇒
非 pin 树报 `rc=2` ＋ 真因 ＋ 修法 ✓，★**刀一行未动** ✓（＋11/−0）。

⇒ ★故「`rc=1`」在本目录里**不再意味着一件事**：**看码 ＋ 看出声面，两者同读**（体例见【附二】第三条）。

## 1. `check-refs.mjs` —— 引用核（清单与实存）

| | |
|---|---|
| **清单** | 核对 `stories/babel/scenarios/scenarios.json` 里每处引用的实存性，包括 `路径:行` 是否存在、行号是否在范围内、该处是否逐字含其声明的符号，而不是靠「同字段 token 猜测」。加上 `--docs` 则进入 docs 面的报告态，每次打印明账，不做硬判。★另有 `--require-symbols`（`books#271` 余项裁）：把「仅范围核 N」从**明账**升为**机械判据**（N>0 即红，逐条具名）——**默认关**，因为改默认是判据面的语义变更；亦可 `REFS_REQUIRE_SYMBOLS=1` 打开。 |
| **固定命令** | `node tools/check-refs.mjs --engine <引擎检出目录>`；`… --docs`（报告态）；`… --require-symbols`（明账升机械判据） |
| **期望读数** | 正向输出是 `✓ 清单引用核通过`，在 pin `50944035` 的干净检出上现读为 `通过 46｜不符 0　★明账：仅范围核 38`，退出码为零。读数依赖 `--engine` 指向的检出，实测同一棵树配空引擎目录会得到 `通过 25｜不符 21`，因此引用现读结果时必须写明装置面，不可只给裸数字，因为它随 pin 变化。报告态的输出是 `扫 10 md｜引用 16｜不符 0｜已豁免 16`，退出码为零。反向情形包括任一 `✗ […] …**不含**其声明的符号`，此时退出码为一；配置损坏时退出码为二。★带 `--require-symbols` 时，另有反向形：清单里只要有**没写显式符号**的引用 ⇒ 退出码为一，并逐条印 `· 无符：[场景 ⁄ 字段] 路径:行`（✗ 只报个数）；默认（不带开关）时这一项**只出声、不回红**。 |
| **设立理由** | 把「抄写会错」机械化。本会话的引用核曾当场抓出抄错目录名，`dnd5e` 实为 `dnd-5e`，另抓出三处真错，分别是 `engine/README.md` 的限定、`equipment-3e.md:3220` 的短名陷阱与自伤引用形。判据形是逐引用显式声明符号。 |

## 2. `check-refs.knives.sh` —— 引用核的正向刀

| | |
|---|---|
| **清单** | 共七刀，逐刀故意破掉一处，例如删掉 `ref()` 与声明之间的联系、写错行号或写错符号，要求每条都红，并且红在对的支。 |
| **固定命令** | `bash tools/check-refs.knives.sh` |
| **期望读数** | 正向输出是 `✓ 7/7 刀均红在对的支`，退出码为零。反向情形是任一刀不红，此时退出码为一，说明门在空转。 |
| **设立理由** | 门必须自证红得了，恒绿的门等于装饰。本仓纪律是每个门都要配一把能让它变红的刀。 |

|---|---|

| | |
|---|---|
| **清单** | 把构建产物，也就是单文件 HTML，放进真浏览器与真 DOM 跑一遍，回答产物在真 DOM 里是否跑得起来，而不是靠 jsdom 得到假绿。 |

## 5. `rehearse-workflow.py` —— 工作流拆分布局演练

| | |
|---|---|
| **清单** | 抽取 CI 工作流的 `run:` 块，在拆分仓布局下按同样的 flags 逐条执行并兑现 `working-directory`，回答工作流在拆分布局下能不能跑。 |
| **固定命令** | `ENGINE=<引擎检出> GITHUB_WORKSPACE=<工作区> python3 tools/rehearse-workflow.py`，以及 `ENGINE=<检出> bash tools/rehearse-workflow.knives.sh`（三刀） |
| **期望读数** | 正向输出是 `── 工作流 run 块逐条演练：通过 N｜失败 0`，现读为 9 比 9，另有 `✓ 引擎仓没被写脏（归因 (b)）`，退出码为零。反向情形是任一步退出码非零，此时失败计数加一。缺少 `WF` 档或缺少 `ENGINE` 时给出具名退出码二，而不是栈回溯。刀的输出是 `── 通过 3｜失败 0`。 |
| **`$GITHUB_ENV` 语义** | 演练器提供 `$GITHUB_ENV` 档并跨步回读，与真 GitHub 一致，也就是写入对后续步生效，且每步一份新档。这属于 `#111` 的同族修复。先前不设该变量时，`>> "$GITHUB_ENV"` 的步在 `set -u` 下会假红三步，分别是读 pin、构建与构建可复现。此外只给空档不够，实测读 pin 转绿而构建仍然报 `VER: unbound`。 |
| **设立理由** | 它属于 pin 升版批的第三步，体例见 `#83`。实证之一是 `--dump-facts` 式的只读开关并不会改动退出码。本演练曾正确报红，情形是拿新检出而声明件仍指旧 pin，此时「核检出等于 pin」的自证当场判为不一致，证明守卫有效。 |

## 6. `refs-exemptions.json` —— docs 面豁免清单（配置件）

| | |
|---|---|
| **清单** | 它是 `check-refs.mjs --docs` 的豁免台账，登记本仓 README 等仓元数据里的路径形引用。被豁免者进入「已豁免」类并计数出声，而不是静默丢弃。配置损坏时退出码为二。 |
| **固定命令** | 没有独立命令，它由 `node tools/check-refs.mjs --engine <检出> --docs` 消费。查看台账本身用 `cat tools/refs-exemptions.json`。 |
| **期望读数** | 报告态读数中显示 `已豁免 16`，若显示零则说明台账没被读到。配置损坏时退出码为二，而不是回落到空豁免。 |
| **设立理由** | 这是豁免面的哲学。`docs/**` 不在旧门的扫描面内，旧门的扫描面是 `SCAN_DIRS=src/tests/stories`，因此 books 侧新增了 `--docs` 报告态，而不做硬判。前缀守卫曾用结构式写法 `/^[\w./-]+\/\*\*$/`，一条即可挡四种形态。 |

## 7. `check-refs-recheck.mjs` —— 引用核的独立复算器（第二双眼睛）

| | |
|---|---|
| **清单** | 它做两件事。第一件是作为同名四判据的第二实现，与 `check-refs.mjs` 逐字同形。第二件是独立清点，枚举整份清单的全部字符串，而不使用被核对象的字段白名单，因此对账差集就是覆盖缺口。此外它还检查降级面，也就是符号声明落在搜索窗之外的情形。 |
| **固定命令** | `node tools/check-refs-recheck.mjs --engine <引擎检出目录> --compare`，以及 `node tools/check-refs-recheck.mjs --selftest`（十二刀） |
| **期望读数** | 正向输出是 `✓ 复算：与 check-refs.mjs 一致，且未扫面已点名`，退出码为零，此时四项读数逐项一致，分别是处、符号核、仅范围核与不符。自检的输出是 `✓ recheck 自检全部如期（12/12 刀）`，退出码为零。反向情形是任一项不等，此时退出码为一。缺少引擎根时给出具名退出码二，而不是栈回溯。 |
| **设立理由** | 它体现「同一判据两套实现互核」的思路。如果本体在判据面上存在缺口，第二实现同样看不见，因此独立性靠清点面来买，而不是靠白名单。实测曾抓到 `[span2-vermin-hp-ac-per-item]` 字段为「同锚分案」的引用 `bombardier-beetle.js:4`，其内容正确但门看不见，另抓到一处降级面。 |

## 附二：判据与刀的写法（体例）

本目录的判据件在写法上守两条，两条互为表里。第一条让读数可读，第二条让读数可信。

**第一条，判据必须具名。** 任何一条红都要在报出行里写清是哪一面、哪一个量、期望多少、实得多少，
使读的人不必回头去读判据源码就能定位。这一条同样适用于绿：绿也要带读数，否则「通过」二字无从复算。

**第二条，下刀必须四步。** 这四步是本席在 `books#152` 一类的笔次里吃出来的，写在此处供同目录的工具作者照做。

第一步是**先从源码读出真变量名与行号，不要凭记忆写**。我曾在按记忆猜出的变量名上下了两刀，
两刀都「成功运行」而没有命中任何锚句，于是得到的是假绿，看上去像「判据没有咬合」。
刀没命中与刀没效果是两件事，而前者以绿的形式出现，因此比红更难发现。

第二步是**改刀之后先回读被测的那一档，确认目标行确实已经变成刀形，再看退出码**。
这一步是评审补上的，它盖住的是「读了源码、锚句却仍不匹配」这一面：替换的目标串可能在档里出现多次，
也可能缩进与源码不一致，那时刀同样落空，而退出码照样好看。回读的动作是cat 出那几行来对，不是凭印象。

第三步是**刀后取退出码与出声面同读**。只看退出码会把「根本没跑起来」读成「通过」，
而只看出声面会把「装置抛错」读成「判据报红」。

第四步是**附同一装具的前后对跑**。改动前与改动后各跑一次，两处读数都附上，读的人才能复算。
这里要说明的是「同一装具」四个字的分量：换一支装具跑第二遍不叫复现，
那是同一装具跑两次的另一种写法，两者的结论都只覆盖那一支装具。

## 附三：合前检查（★每票合入前跑一遍 · 两条）

这两条是 2026-10-04 一天里、用四笔「看着干净、合了会坏」的票换来的：
`books#296`／`#303`／`#305`／`#310` 各自**基座落后** ⇒ 对**现 main** 的 diff 里带着**回退行**
（合入会抹掉别的笔刚合的东西：`tests/gates/*`、`tools/e2e-1763-panels.mjs`、`tools/README.md` 的登记行…）。

**★基座落后的读法（`books#315` 加固 · 2026-10-05）**：基座落后时，**回退面须看「合并结果」** ——
`git merge --no-commit --no-ff <票头>`（干跑）或 **3-dot** `git diff --numstat <main>...<票头>`（＝ `check-premerge` ② 的口径 ✓）；
★**✗ 不可**用 **2-dot** `git diff <main> <票头>` 两树直比 —— 那会把 **main 自己那几档的推进**也算成差异 ⇒ **误报大批「只删不加」**
（本席 2026-10-05 在 `books#334` 上实栽一次 ✗）。本器落后时会**自动印**这条提示 ✓。
★`mergeable_state=clean` **看不出来**这一类 —— 它只答「能不能自动合」，✗ 不答「这条分支是不是握着旧版本的内容」。

### 检查一：基座同尖 ＋ 回退行 0（★合前必跑）

```console
$ MB=$(git merge-base origin/main <票头>)
$ [ "$MB" = "$(git rev-parse origin/main)" ] || echo "✗ 落后：先 rebase 到现 main"
$ git diff --numstat origin/main <票头> | awk '$1=="0"{print "✗ 回退行（只删不加）："$3}'
```

判据：**merge-base 必须等于现 main（同尖）**，且对现 main 的 diff 里**没有「只删不加」的档**。
两条任一不成立 ⇒ ★**先 rebase，再谈内容**：内容面可以已经核好，基座旧照样拦住（`books#296` 那次，
对当时 main 的 diff 是 22 档 ＋103/−1468 ⇒ 合了会删掉一整天新落的装置件）。

### 检查二：patch-id 证「纯 rebase」（⇒ ★读数不重跑的硬证）

被要求 rebase 时，作者常要重推一版。**若这一版只是换基座**，那先前已核过的读数（文风／链接／跑数／
刀）**不必重跑** —— 但这句话要有据，据就是 **patch-id**（同一改动集在不同基座上的稳定指纹）：

```console
$ 旧=$(git diff $(git merge-base origin/main <旧头>) <旧头> | git patch-id --stable | cut -d' ' -f1)
$ 新=$(git diff $(git merge-base origin/main <新头>) <新头> | git patch-id --stable | cut -d' ' -f1)
$ [ "$旧" = "$新" ] && echo "✓ 纯 rebase（内容面逐字同）⇒ 读数沿用" || echo "✗ 内容有变 ⇒ 读数须重跑"
```

★实例（`books#310`）：rebase 前后 `72edfe5fe69e08d8223022931581a65306a19c38` **逐字同** ⇒
该笔 T 面读数（四档 `--body` 全 rc=0、`--selftest` 17/17、链接 43/0）**沿用不重跑** ✓。
★反之 patch-id 不同 ⇒ 说明**不只是换基座**（内容改了）⇒ 该核的全核 ✓。

### 两条之外、仍要做的两件

- **触发面**：★只改 `tests/gate-001/**` 的笔，其触发面自证只能在**合入后**（合并前 CI 跑的是旧触发面，
  见 `books#313` 的注 ✓）；`docs/**` 之类不在 `paths` 里的笔，其「CI 绿」是**空条件**（✗ 不是「未绿」）✓。
- **装置面**：读数一律取自**干净树**（`git archive origin/main` 或等价），且**先读该树自己的
  `.github/engine-ref.json`**，✗ 别拿别的树跑；装置错（rc=2）与判据红（rc=1）分开记（见上文「退出码三分」）。
