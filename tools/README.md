## 1. `check-refs.mjs` —— 引用核（清单与实存）

| | |
|---|---|
| **清单** | 核对 `stories/babel/scenarios/scenarios.json` 里每处引用的实存性，包括 `路径:行` 是否存在、行号是否在范围内、该处是否逐字含其声明的符号，而不是靠「同字段 token 猜测」。加上 `--docs` 则进入 docs 面的报告态，每次打印明账，不做硬判。★另有 `--require-symbols`（`books#271` 余项裁）：把「仅范围核 N」从**明账**升为**机械判据**（N>0 即红，逐条具名）——**默认关**，因为改默认是判据面的语义变更；亦可 `REFS_REQUIRE_SYMBOLS=1` 打开。 |
| **固定命令** | `node tools/check-refs.mjs --engine <引擎检出目录>`；`… --docs`（报告态）；`… --require-symbols`（明账升机械判据） |
| **期望读数** | 正向输出是 `✓ 清单引用核通过`，在 pin `50944035` 的干净检出上现读为 `通过 46｜不符 0　★明账：仅范围核 38`，退出码为零。读数依赖 `--engine` 指向的检出，实测同一棵树配空引擎目录会得到 `通过 25｜不符 21`，因此引用现读结果时必须写明装置面，不可只给裸数字，因为它随 pin 变化。报告态的输出是 `扫 10 md｜引用 16｜不符 0｜已豁免 16`，退出码为零。反向情形包括任一 `✗ […] …**不含**其声明的符号`，此时退出码为一；配置损坏时退出码为二。★带 `--require-symbols` 时，另有反向形：清单里只要有**没写显式符号**的引用 ⇒ 退出码为一，并逐条印 `· 无符：[场景 ⁄ 字段] 路径:行`（✗ 只报个数）；默认（不带开关）时这一项**只出声、不回红**。 |
| **设立理由** | 把「抄写会错」机械化。本会话的引用核曾当场抓出抄错目录名，`dnd5e` 实为 `dnd-5e`，另抓出三处真错，分别是 `engine/README.md` 的限定、`equipment-3e.md:3220` 的短名陷阱与自伤引用形。判据形是逐引用显式声明符号。 |

## 5. `rehearse-workflow.py` —— 工作流拆分布局演练

| | |
|---|---|
| **清单** | 抽取 CI 工作流的 `run:` 块，在拆分仓布局下按同样的 flags 逐条执行并兑现 `working-directory`，回答工作流在拆分布局下能不能跑。 |
| **固定命令** | `ENGINE=<引擎检出> GITHUB_WORKSPACE=<工作区> python3 tools/rehearse-workflow.py`，以及 `ENGINE=<检出> bash tools/rehearse-workflow.knives.sh`（三刀） |
| **期望读数** | 正向输出是 `── 工作流 run 块逐条演练：通过 N｜失败 0`，现读为 9 比 9，另有 `✓ 引擎仓没被写脏（归因 (b)）`，退出码为零。反向情形是任一步退出码非零，此时失败计数加一。缺少 `WF` 档或缺少 `ENGINE` 时给出具名退出码二，而不是栈回溯。刀的输出是 `── 通过 3｜失败 0`。 |

| | |
|---|---|
| **清单** | 它做两件事。第一件是作为同名四判据的第二实现，与 `check-refs.mjs` 逐字同形。第二件是独立清点，枚举整份清单的全部字符串，而不使用被核对象的字段白名单，因此对账差集就是覆盖缺口。此外它还检查降级面，也就是符号声明落在搜索窗之外的情形。 |
| **固定命令** | `node tools/check-refs-recheck.mjs --engine <引擎检出目录> --compare`，以及 `node tools/check-refs-recheck.mjs --selftest`（十二刀） |

## 8. `e2e-drive.mjs` —— 真产物的驾驶层（读档往返、自环与正文行）

|---|---|
| **清单** | 它通过 `import` 而非复制来使用 `e2e-harness.mjs` 的原语，并加上一层驾驶，包括读档往返，涉及 `Save.slots.save` 与 `Save.slots.load` 以及 `Engine.show()`；还包括自环就地重绘、正文行读数与 State 直铺。它的硬判面标记为 R，指读档往返与导航形，方向是两向；另一个硬判面标记为 L，指同地点读档后地图场景头须重印，出处 `books#136`，方向同为两向，即先断装置看得见头、再断读档确实回滚；第三个硬判面标记为 M，指 L5 选择制事件面（抽中的两类出现为按钮、未抽中的类不出现、择一后两类一起退场而基础遭遇仍在），出处 `books#133`，抽签靠注入随机源钉死；第四个硬判面标记为 N，指工具耐久制的工具门（该层没有对应工具时抽中的「采集」不出按钮，给上工具则出），出处同为 `books#133`，读数靠注入随机源与就地清背包钉死；第五个硬判面标记为 O，指 L9 头目弧的唯一出口（L9 的可用出口只有「前进」一条；对照层 L8 两条都在），出处 `books#133` 笔 3，读数靠注入随机源钉死；明账面标记为 S 与 I，挂票号，可用 `--require <面>` 升为硬判。第六个硬判面标记为 Q（`books#188`）：战斗面两块 —— 敌面板（体力档位／有效 AC／已见动作）与治疗读数（预计恢复／剩余次数），读数是发真实的 `battle:turnEnd`／`item:used`／`battle:end` 后读宿主文本，控制臂是「不发事件则两块皆空」。 |

## 9. `check-norms-symbols.py` —— 正文文风符号复核器（判定面与行文面分类）

| 项 | 内容 |
|---|---|
| **清单** | 它按行判定正文里的六个符号该如何处置。勾叉在判定位置保留，判定位置有三种，即表格格里内容本身即记号、清单条目正文以记号开头、行首即记号且整行很短。连接与强调符则任何位置都须清零，包含表格行、清单条目与判定行在内。它另按例外第五类摘除围栏代码块、行内反引号、引用行与行内引号内的内容，因此这些面上的符号不计入。 |
| **固定命令** | `python3 tools/check-norms-symbols.py --body <正文档>` 读单篇正文；`python3 tools/check-norms-symbols.py --selftest` 跑判别力自证。 |
| **期望读数** | 正向是报告「判定面勾叉 N（保留）｜须清零符号 0」，退出码为零。`--selftest` 的期望读数是「判别力自证：17/17 如期」。反向是任一须清零符号残留，此时退出码为一并逐处打印行号与该行内容。 |
| **设立理由** | 本仓的第二波正文清扫以票面正文为对象，而清扫前后的读数须有人能复算。判定面与行文面的分界是本轮口径的核心，且这条分界在领队勘误之后变成「勾叉按位置分，连接与强调符不分位置」，容易记反。因此把这套判定写成器，并以十七条正反例自证判别力，使读数与判据都不依赖操作者的记忆。它的底版是 `gsvector` 仓开发者席的 `check1899` 族（第六修版），该底版**不在任何仓的在册树上**，故本件不给路径；本席只读取用并加了单篇正文模式与自证面。口径出处见 `gsvector-process#325`。 |

## 附二：判据与刀的写法（体例）

本目录的判据件在写法上守两条，两条互为表里。第一条让读数可读，第二条让读数可信。

**第一条，判据必须具名。** 任何一条红都要在报出行里写清是哪一面、哪一个量、期望多少、实得多少，
使读的人不必回头去读判据源码就能定位。这一条同样适用于绿：绿也要带读数，否则「通过」二字无从复算。

**第二条，下刀必须四步。** 这四步是本席在 `books#152` 一类的笔次里吃出来的，写在此处供同目录的工具作者照做。

第一步是**先从源码读出真变量名与行号，不要凭记忆写**。我曾在按记忆猜出的变量名上下了两刀，
两刀都「成功运行」而没有命中任何锚句，于是得到的是假绿，看上去像「判据没有咬合」。
刀没命中与刀没效果是两件事，而前者以绿的形式出现，因此比红更难发现。

第二步是**改刀之后先回读被测的那一档，确认目标行确实已经变成刀形，再看退出码**。
这一步是评审补上的，它盖住的是「读了源码、锚句却仍不匹配」这一面：替换的目标串可能在档里出现多次，
也可能缩进与源码不一致，那时刀同样落空，而退出码照样好看。回读的动作是cat 出那几行来对，不是凭印象。

第三步是**刀后取退出码与出声面同读**。只看退出码会把「根本没跑起来」读成「通过」，
而只看出声面会把「装置抛错」读成「判据报红」。

第四步是**附同一装具的前后对跑**。改动前与改动后各跑一次，两处读数都附上，读的人才能复算。
这里要说明的是「同一装具」四个字的分量：换一支装具跑第二遍不叫复现，
那是同一装具跑两次的另一种写法，两者的结论都只覆盖那一支装具。

## 10. `balance-babel.mjs` —— 战斗跑分器（LegacyBattleRunner）
