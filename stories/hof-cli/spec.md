# 《灰港送灯》CLI 原型规格

References [#570](https://github.com/sagitrs/sgstory-books/issues/570)。规格/参数先于实现写下；这是试作默认值，不是平衡裁定、发布批准或商业游戏规则的复刻。原创故事、节点、敌组、装备名称与文字由本次实现作者撰写；只借鉴路线事件、整场战斗、跨局解锁的循环形式，未导入外部卡牌或素材。

## 完整循环与数据边界

玩家替灰港修复熄灭的灯塔。营地出发，先选沼泽/崖道；通关后解锁第三条潮渠。经资源事件、商店、一次整场伏击、第二次林地/沙地路线选择、祠堂、精英守卫，最后点亮灯塔。12个旅程节点加1个营地；每次旅程只经过选中的分支，不宣称每局访问12个节点。节点图无回边，买卖/装备/用药不重复节点奖励。

引擎接口1负责选项、RNG、动作日志、保存和原子提交；游戏不复制引擎。状态分为 `profile`（胜/败/撤退计数及已解锁集合）与 `run`（本局序号、节点、资源、装备、已过节点、战果和短反馈），同一引擎事务提交。开始下一局保留profile，重新初始化run，不重置引擎RNG。

手动 `save` 同时保存这两个命名空间。跨进程恢复只依赖该档；不另写隐式账户档，不自动保存，未保存退出会丢本进程的新进度。回读旧档会回到旧长期进度；这不是不可回滚在线账户，也不承诺防篡改、断电耐久或并发事务。

## 试作参数

| 面 | 默认值与约束 |
|---|---|
| 起手 | 生命20、金币10、粮食8；普通出发无装备/药 |
| 粮食 | 转到下一节点耗1；选沼泽/沙地路线额外耗1；不足以支付则拒绝，不扣其他资源 |
| 粮尽 | 抵达后粮食为0时仅能合法撤退；仍能查询/存读。不能领取当前节点奖励或在商店补救 |
| 撤退 | 计一次撤退、结束本局，不计胜败、不解锁、不发通关奖励 |
| 死亡 | 生命0，本局金币减半向下取整、粮食清零、道具和装备清空；不发战胜或通关奖励 |
| 通关 | 点灯时给本局金币8，胜场计一次，首次解锁潮渠捷径；不跨局累计金币 |
| 死亡解锁 | 第一次死亡解锁守夜护符，下一局可选择带护胸出发；护符是可选初装，不改RNG |
| 长期上限 | 已结局总数最多100万；到上限不再出发，已存在档仍可查询/保存 |
| 消耗品 | 回春药恢复6生命、上限20，使用扣1；满血拒用。只能整场战前/战后使用，非逐回合战斗 |

## 整场战斗

普通敌组为灰沟鼠群、崖道掠鸟、食砂犬，精英为失灯守卫。潜在攻击次数只由敌数乘耐战决定，分别4、3、4、8。强度只定伤害骰（6、4、6、8面），不再减少次数。

每次潜在攻击先掷1–100，若不大于有效反击百分比才掷伤害骰。有效百分比为 `基础概率 - 武器档×15 - 灯祝福×15 + 诅咒×15`，截在5到95之间。武器档分别无武器0、短刃1、长刀3；不同装备取当前一件，不叠加。护甲分别无0、护胸1、鳞甲3；有效反击伤害为 `max(0, 骰值 - 护甲)`。没有有效反击不掷伤害骰；护甲可把一次有效反击减为0，不强制扣血。生命归零即停止余下攻击；潜在次数与实际判定次数分列。

单个battle动作一次性提交随机消费、生命、粮食/路线推进、胜利奖励或死亡和长期记录。失败或拒绝不能留下半场资源/RNG更改。三组普通敌基础概率为70、65、70，精英75；这些概率和武器/护甲值仍需人工/模型试玩，不宣称合理胜率。

## 内容与选择

| 节点 | 可见选择及实际代价 |
|---|---|
| 岔路口 | 沼泽耗2粮；崖道耗1粮；已通关的潮渠耗1粮，直接到商店 |
| 沼泽 | 捞漂粮：随机得1–3粮；与撑船人交易：用2粮换4金币；然后各耗1粮到商店 |
| 崖道 | 取铜矿：失4生命、得6金币；扶绳通过：失2生命、得3金币；然后耗1粮到商店 |
| 潮渠 | 捷径直接抵商店，不额外发事件奖励 |
| 商店 | 6件物品；购买/换装/用药均留在商店，离开耗1粮到伏击 |
| 伏击 | 沼泽来路遇鼠群，其他来路遇掠鸟；胜后金币4并前往第二岔路，败则死亡 |
| 第二岔路 | 林地耗1粮；沙地耗2粮；两处是真实不同事件，不仅换标题 |
| 林地 | 采干粮得3粮；救守林人用2粮、恢复7生命并得灯祝福；再耗1粮到祠堂 |
| 沙地 | 打食砂犬胜后得4粮/3金币；或付2金币避战；再耗1粮到祠堂 |
| 祠堂 | 献2金币得灯祝福；取诅咒钱得5金币并带诅咒；或不取；再耗1粮到精英 |
| 精英 | 一次整场战斗；胜后得6金币并耗1粮到灯塔；败则死亡 |
| 灯塔 | 点灯通关，或主动撤退；终局只能再次出发/带护符出发或引擎存读/退出 |

献灯在已有祝福时拒绝；救人仍可治疗但不会叠加同祝福。生命损失事件可自然导致死亡，死亡同样不发该事件的利益。粮食代价必须包括事件支出加旅行支出，不能先奖励再查前置。

| 商店物品 | 价格 | 实际规则 |
|---|---|---|
| 短刃 | 3 | 武器档1，购买自动装备，背包可换回 |
| 长刀 | 6 | 武器档3，购买自动装备，不和短刃叠加 |
| 护胸 | 3 | 护甲1，购买自动装备 |
| 鳞甲 | 6 | 护甲3，购买自动装备 |
| 行粮 | 3 | 粮食加5，可重复购买 |
| 回春药 | 2 | 背包药1瓶，携带最多3瓶 |

守夜护符已解锁时商店每件便宜1金币，下限1。无钱、装备重复、药满等拒绝均须具名，并且不扣费、不抽随机。装备换装实际参与下一场反击概率/伤害计算。

## 验证约束与未覆盖

单元可直接构造规则夹具及确定随机序列，分别核概率端点、武器单计、自然无伤、护甲、死亡/胜利、资源前置、节点一次性、存读与原子性。正常CLI玩家族只走 stdin/stdout，正常启动seed可登记，不中途改RNG、造状态、改档或调用游戏/引擎API；至少完整胜局、自然败局/撤退、两分支、购买/装备、整场战斗、跨进程恢复及下一局解锁。

两族登记实际文件与具名非空用例，问题总数按产品失败/环境作废/未覆盖分别出声；未跑不计过。刀只动本次游戏的临时副本，四步核基线、具名红、恢复、字节相同，不动正式引擎pin树。

本次不覆盖正式商业平衡、视觉/网页、Windows/macOS、自动账户长期进度、模型费用/试玩、多槽策略、迁移旧游戏档、实时/逐回合战斗或安全沙箱。既有网页pin、构建与发布冻结保持原账。
