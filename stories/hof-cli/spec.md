# 《灰港送灯》CLI 原型规格

原型 References [#570](https://github.com/sagitrs/sgstory-books/issues/570)；当前剧情决策版 References [#572](https://github.com/sagitrs/sgstory-books/issues/572)、[#597](https://github.com/sagitrs/sgstory-books/issues/597)，增量规格见 [event-spec.md](event-spec.md)。规格/参数先于实现写下；这是试作默认值，不是平衡裁定、发布批准或商业游戏规则的复刻。原创故事、节点、敌组、装备名称与文字由本次实现作者撰写；只借鉴路线事件、整场战斗、跨局解锁的循环形式，未导入外部卡牌或素材。

## 完整循环与数据边界

玩家替灰港修复熄灭的灯塔。营地出发，先选沼泽/崖道；通关后解锁第三条潮渠。经资源事件、商店、一次整场伏击、第二次林地/沙地路线选择、祠堂、精英守卫，最后点亮灯塔。12个旅程节点加1个营地；每次旅程只经过选中的分支，不宣称每局访问12个节点。节点图无回边，买卖/装备/用药不重复节点奖励。

引擎接口2负责选项、RNG、动作日志、保存和原子提交；游戏不复制引擎。状态分为 `profile`（胜/败/撤退计数及已解锁集合）与 `run`（本局序号、地图/节点、资源、装备、已过节点、战果、林地阶段/救助记忆/同地图后果和短反馈），同一引擎事务提交。开始下一局保留profile，重新初始化run，不重置引擎RNG。

手动 `save` 同时保存这两个命名空间。跨进程恢复只依赖该档；不另写隐式账户档，不自动保存，未保存退出会丢本进程的新进度。回读旧档会回到旧长期进度；这不是不可回滚在线账户，也不承诺防篡改、断电耐久或并发事务。

## 资源与道具模型

资源与装备由**一张条目定义表**（`content.mjs` 的 `ITEMS`）决定：类别与上限都在表里，不在代码里另设第二份。

| 类别 | 条目 | 上限 | 说明 |
|---|---|---|---|
| `resource` | 生命、金币、粮食 | 20、999、999 | 不占背包格；生命归零即死亡 |
| `consumable` | 回春药 | 3 | 使用恢复6生命；只能整场战前/战后用 |
| `gear` | 短刃/长刀（武器，档位1/3）、护胸/鳞甲（护甲，有效伤害减1/3） | 各1 | 买下即穿戴，不叠加 |

- **单一数量源**：本局资源与在身条目都记在一张数量表里（`run.counts`）；装备栏另记（`run.equipped`，值为 `none` 或该槽位的装备 id）。**背包是派生视图**（非资源且数量大于0的条目），不另存一份。
- **派生面的枚举顺序＝条目定义表的顺序**（`ITEMS` 的声明序）：`背包：` 行按条目的数量重复列出（2 瓶药写两次），逐条详情与换装选项按定义表顺序。这是本版**具名的行为差异**之一 —— 现版按「获得顺序」列出；要保留获得顺序，就得为资源模型再引入一份插入序状态，而那正是本版要拆掉的双写。
- **增删的单一入口**：资源与道具的变动都经 `grant`／`spend` 两个纯函数。`grant` 超上限即**具名拒绝**，`spend` 不足即具名拒绝，两者都不静默截顶。**截顶是调用点的行动规则**（例如用药恢复 `min(6, 上限 − 现值)`），不是 `grant` 的语义。

| 商店 | 价格与折扣仍按既有参数（护符老客每件少1，下限1）；行粮是「立即转化为粮食5」的购买动作，不留背包 |

## 存档与旧档

档只含长期进度与当前局；**本版不迁移旧档**。

- 游戏版本 `version` 为 **4**（同地图点位绑定由单条键改为具名集合 `bindings[]`；此前 3 为资源模型改版、2 为剧情判定短链、1 为初版）；引擎接口版本由引擎单独声明。
- `load` 遇版本不符时提示「**旧存档不可用**（本版不支持迁移）」：接口不符走 `SAVE_VERSION`，仅游戏内容版本不符走 `SAVE_GAME`。两条路径都**保留当前会话、不改动档文件、不显示任何来自旧档的内容**（校验先于替换；禁止「先加载或先显示旧档，再报错」）。

## 整场战斗

普通敌组为灰沟鼠群、崖道掠鸟、食砂犬，精英为失灯守卫。潜在攻击次数只由敌数乘耐战决定，基础分别4、3、4、8。强度只定伤害骰（6、4、6、8面），不再减少次数。#572 救助链的塔门协同仅对本场 keeper 副本把耐战4改为2，潜在次数4；共享基础敌参不改，见增量规格。

每次潜在攻击先掷1–100，若不大于有效反击百分比才掷伤害骰。有效百分比为 `基础概率 - 武器档×15 - 灯祝福×15 + 诅咒×15`，截在5到95之间。武器档分别无武器0、短刃1、长刀3；不同装备取当前一件，不叠加。护甲分别无0、护胸1、鳞甲3；有效反击伤害为 `max(0, 骰值 - 护甲)`。没有有效反击不掷伤害骰；护甲可把一次有效反击减为0，不强制扣血。生命归零即停止余下攻击；规则返回潜在次数与实际判定次数供断言，玩家反馈仅呈现实际反击与受伤，不默认显示隐藏概率/伤害公式。

单个battle动作一次性提交随机消费、生命、粮食/路线推进、胜利奖励或死亡和长期记录。失败或拒绝不能留下半场资源/RNG更改。三组普通敌基础概率为70、65、70，精英75；这些概率和武器/护甲值仍需人工/模型试玩，不宣称合理胜率。

## 内容与选择

| 节点 | 可见选择及实际代价 |
|---|---|
| 岔路口 | 沼泽耗2粮；崖道耗1粮；已通关的潮渠耗1粮，直接到商店 |
| 沼泽 | 捞漂粮：随机得1–3粮；与撑船人交易：用2粮换4金币；然后各耗1粮到商店 |
| 崖道 | 取铜矿：失4生命、得6金币；扶绳通过：失2生命、得3金币；然后耗1粮到商店 |
| 潮渠 | 捷径直接抵商店，不额外发事件奖励 |
| 商店 | 6件物品；购买/换装/用药均留在商店，离开耗1粮到伏击 |
| 伏击 | 沼泽来路遇鼠群，其他来路遇掠鸟；胜后金币4并前往第二岔路，败则死亡 |
| 第二岔路 | 林地耗1粮；沙地耗2粮；两处是真实不同事件，不仅换标题 |
| 林地 | 拿3份干粮或付2粮，都留在林地继续遭遇判定；给粮改善结果分布。避开伏击或整场战胜后才完成；救助完成最多恢复7生命/非叠加祝福并绑定后续塔门协助；最后耗1粮到祠堂。精确结果见增量规格 |
| 沙地 | 打食砂犬胜后得4粮/3金币；或付2金币避战；再耗1粮到祠堂 |
| 祠堂 | 献2金币得灯祝福；取诅咒钱得5金币并带诅咒；或不取；再耗1粮到精英 |
| 精英 | 一次整场战斗；胜后得6金币并耗1粮到灯塔；败则死亡 |
| 灯塔 | 点灯通关，或主动撤退；终局只能再次出发/带护符出发或引擎存读/退出 |

献灯在已有祝福时拒绝；救助实际完成后才治疗，不会叠加同祝福。生命损失事件可自然导致死亡，死亡同样不发该事件的利益。粮食代价必须包括事件支出加旅行支出，不能先奖励再查前置。

| 商店物品 | 价格 | 实际规则 |
|---|---|---|
| 短刃 | 3 | 武器档1，购买自动装备，背包可换回 |
| 长刀 | 6 | 武器档3，购买自动装备，不和短刃叠加 |
| 护胸 | 3 | 护甲1，购买自动装备 |
| 鳞甲 | 6 | 护甲3，购买自动装备 |
| 行粮 | 3 | 粮食加5，可重复购买 |
| 回春药 | 2 | 背包药1瓶，携带最多3瓶 |

守夜护符已解锁时商店每件便宜1金币，下限1。无钱、装备重复、药满等拒绝均须具名，并且不扣费、不抽随机。装备换装实际参与下一场反击概率/伤害计算。

## 玩家细节视图（inspect）

引擎接口v2诊断面在本游戏侧的消费者。根页四类恒列出（主动道具/被动道具（含装备）/状态（正面＋负面）/情报），每类条目带**可见**计数，空类显示「暂无」。

可见性判据只读本局状态，写在 `content.mjs` 的条目定义里（单一事实源）：回春药与四件装备按 `bag` 计（装备中的件也在 `bag` 内）；灯祝福/诅咒按布尔位；守林人按其阶段（`unmet` 开局即有 ⇒ **不可见**）；地图绑定按 `bindings.length > 0`；地图恒可见（已过节点与潮渠解锁态都在 `map` 串里）；守林人线索、塔门线索与其来源同判据。未遭遇/未获得的条目**不生成**，不是「列出后标为不可选」——这是 #597 B 展示边界的延伸。行粮不入枚举：购买即转粮食、不进背包。

条目 id 复用内容定义（`tonic`、`knife`、`blessing`、`forester-aid`、`intel-map`…），不随背包顺序、换局或存读变化。详情文本与 `bag`/`map` **同源**：装备与道具用 `bag` 逐条详情的那一个函数，地图用 `map` 查询的那一个函数。浏览纯读：不改状态、随机、动作数与日志。

结构化数据（`data`）只在**详情页**返回，只在 `--debug` 开且玩家在该页输入负数时打印到 stderr，默认不显示；它**先过可见性判据**，故隐藏条目的字段不可能经它泄露。价格、档位与概率修正这类精确参数只出现在这条诊断通道里，不进默认视图。

## 验证约束与未覆盖

单元可直接构造规则夹具及确定随机序列，分别核概率端点、武器单计、自然无伤、护甲、死亡/胜利、资源前置、节点一次性、存读与原子性。正常CLI玩家族只走 stdin/stdout，正常启动seed可登记，不中途改RNG、造状态、改档或调用游戏/引擎API；至少完整胜局、自然败局/撤退、两分支、购买/装备、整场战斗、跨进程恢复及下一局解锁。

两族登记实际文件与具名非空用例，问题总数按产品失败/环境作废/未覆盖分别出声；未跑不计过。刀只动本次游戏的临时副本，四步核基线、具名红、恢复、字节相同，不动正式引擎pin树。

游戏版本4。**版本 1、2、3 的游戏档一律具名 `SAVE_GAME` 拒绝**（引擎报「档为 … vN，本版为 … v4」，两侧版本号都在），失败保留当前会话、不覆盖旧文件；新目录试玩。不写迁移器。中间阶段和后续绑定可手动存读，仍不防更早历史回读。本次不覆盖正式商业平衡、视觉/网页、Windows/macOS、自动账户长期进度、模型费用/试玩、多槽策略、迁移旧游戏档、实时/逐回合战斗或安全沙箱。既有网页pin、构建与发布冻结保持原账。
