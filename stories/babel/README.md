# 巴别之井 · 试玩版（1–20 层）

本目录是可玩的故事，会烘成一个自带 SugarCube、插件和故事源码的单文件网页。测试工具入口见 [`tools/README.md`](../../tools/README.md)，装配自检不能代替真实点击或收益／平衡验收。

## 开局：两条教学入口（并轨常驻）

`:: 开始` 只有两个教学入口：

- 「战斗教学」：从 `L1 苏醒` 学起，一路打上去。
- 「跳过教学」：调用 `直达十层()` 到 `L10-camp`，本 PR 的 Common Hearth／共炉；与步行 `L9 → L10-camp` 和回城卷轴共用落点，不是另一段剧情。

挡路者生命恒减半（`max(1,⌊满/2⌋)`），玩家初始生命恒 ×2。两处源分别为 `world/encounters.js` 的成军和 `world/babel.js` 的开局。不再区分普通／简单，不设难度旗标或面板标记；旧档残留的 `难度` 键不读。

跳过教学走权威口记录三笔账：`已战[L1..L9]`、`已跳过[L1..L9]`（事件阶段已跳过）、`记战果('L9','victory')`（该写口决定引擎进度账或旧 pin 回落）。

起手装备仍是占位基线，真值归 writer／`balance-babel`：淬火长剑（已装）、重木盾、斧头（自带 6 次耐久）、草药糊（自带 2 次）、旧硬币 ×3。直达不证明自然成长或经济平衡。

## 构建与引擎版本

本仓只放故事。`.github/engine-ref.json` 的精确 `ref` 是构建引擎的唯一权威，不跟随引擎 main 漂移。变更 pin 时必须同步 `why`、`checked`，并按该提交重新验收。

```bash
# 从 books 仓根运行；引擎检出必须独立，不移动他人工作树。
mkdir -p "$HOME/tmp"
git clone https://github.com/sagitrs/sgstory "$HOME/tmp/engine"
git -C "$HOME/tmp/engine" checkout "$(node -p "JSON.parse(require('fs').readFileSync('.github/engine-ref.json','utf8')).ref")"
python3 "$HOME/tmp/engine/build.py" "$PWD/stories/babel" --out babel-trial.html
node stories/babel/verify.mjs --engine "$HOME/tmp/engine"
```

故事目录须给绝对路径：`build.py` 的相对路径以引擎根为基准。产物为 `stories/babel/babel-trial.html`，双击即可游玩。`story.json` 声明 `packs:["dnd3"]`，本作只装 D&D 3.5 包和通用 core；包选择的真实生效面由 `tests/gates/pack-manifest.mjs` 检验，缺能力必须报告待判，不能算绿。

现有 `.github/workflows/babel-tests.yml` 检查 pin、构建、单文件、重复构建、场景和装配，并运行门自身的反向自证。新测试须重建包装后执行。

## 怎么玩

用现代浏览器打开网页，从「战斗教学」到「站起来」进入探索；「跳过教学」直接进入 L10 共炉。本版目标是穿过 L19 战果门，到达第 20 层；L20→L21 只定义、不挂图。

| 阶段 | 可做的事与边界 |
|---|---|
| L1–L9 | 逐层首战、事件和采集，保留 L9 头目硬门。塔的步行边只上行；层内／城内往返仍保留 |
| 真死 | 进入本局死亡终局，不复活、不回收肉身；读档和重开是玩家功能，不是世界内复生 |
| L10 | 五栋建筑已经存在，证前可进入、交谈、出售资源、最低休整和购买付费回城卷轴 |
| 居民证 | 指定资源出售累计达候选门槛后，免费取得本局资格；一次开放服务，不逐栋建造／升级 |
| L11–L19 | 用既有战斗、采集、事件与装备继续攀登。居民证不是 L19 的额外头目门 |
| 付费返程 | 卷轴改变位置并执行 `moveTo`／`onEnter`；不重置资源、事件奖励、战果、领取记录或旧农田 |
| L20 | 保留锻造图、材料、军械、马厩与原有治疗。它是本版终点，不回退为 L10 新服务的复制品 |

反馈按 [`PLAYTEST.md`](PLAYTEST.md) 的三栏写，不把测试夹具或候选参数当作试玩者已经认可。

## L10 最简城市（候选）

Design basis：[最简玩法](../../docs/plans/babel/optional/cities/L10-first-city.md)及[来源与状态](../../docs/plans/babel/optional/cities/L10-sources-and-status.md)，实施票 #314。工作名不是作者定名，制度复杂度留在剧情。玩家不购买或经营奴隶，也不承担全城财政、人口、地产或劳务拍卖模拟。

| 既有建筑／工作名 | 证前 | 证后 |
|---|---|---|
| Newcomers' Registry | 查条件、累计进度与城规 | 免费、幂等领证与查资格 |
| Ration House | 常见资源收购、返程卷轴 | 补给目录 |
| Ember Workshop | 交谈、看装备／费用 | 少量装备、按实体选择单件修理 |
| Lamplight Infirmary | 治疗边界说明；共炉保底仍可用 | 活人 HP 照护、逐条创伤诊疗 |
| Common Hearth | 临时落脚、保底休整与生活对白 | 食宿、原件寄存、更多对白及自愿留居选择 |

唯一新增的城市主进度是 `$babelL10 = {sold,resident}`：`sold` 为成功售货的累计贡献，现金消费不会倒扣；`resident` 为本局资格，不是可掉落证件。金币、物品、伤势、楼层和剧情仍走旧系统。

资源目录、价格、门槛、恢复与时间统一在 `setup.BABEL.L10.cfg`。当前目录只计已注册资源 ID；装备、药品、口粮转卖不计贡献，商店不出售同类贡献原料。成功成交才记一次；不足、取消或投递拒绝没有半笔支付。现金不足或掉物不吊销既得资格。

库存交换沿用引擎口径：`take.n` 是库存单位，`give.n` 是新品批数，两者不是同一计数。一批绷带可能包含多次使用。背包事务的浅副本依赖 `withdraw`／`deposit` 只改槽顶层，不能悄悄改为嵌套写入；构造器外部副作用与连续身份流水号不在回滚承诺内。

个人寄存的 `$babelL10Storage` 是原件快照，不是第三种城市评分。原件保留 `entityId`、`charges` 与状态；装备中的物品拒存，投递失败不先删原件。读档和购买前预留寄存身份，避免新品撞号。旧档只补缺域，不追算贡献、不清农田或发补偿。

旧档已有农田在配给屋保留证前收尾：有田才显示，按既有 `DND3.farmCount()` 与 `RPG.harvest(DND3.Player)` 向玩家投递口粮、清掉本次已收农田并记收成。收完隐藏，再次收获拒绝且不重复产出；不记城市贡献、不授居民证，也不恢复图纸建设路线。

保底休整与医院分开：普通非致命倒下仍能看到恢复动作；休整不全清创伤、补物资、恢复道具次数或工具耐久。付费照护不能复活真死者；创伤逐条按既有 `treatTrauma` 检定，掷高和掷低都须验收，缺肢和机械损坏不冒充回血。

### 自由、死亡与留居是三件事

候选「以自由抵偿」有清楚预警及两次可取消确认。普通贫困、未持证、可偿还欠账、非致命倒下、求医或成功逃跑都不自动触发。最终接受后显示「失去自由，本次攀登结束」，不置 HP 为零、不授死亡、不调用复活或增加死亡数。

持证不等于正式留居；自愿选择「留在共炉」是正常归属，不是死亡／失败，也不宣称压迫已消失。两种终局都锁全图动作、出口、道具使用与战斗提交，物品可只读查看；读档和真重开仍可用。`babelRun.终局类型` 保留分类并随旧运行域保存，回归核其取值；本版以独立终局段落呈现区别，不另加面板读取面，背包共用中性的只读提示。其他捕获／奴役触发、数值、工作名及后日谈仍待作者裁定。

### 已核与未核

装配和浏览器断言覆盖交易、资格、服务接线、实例身份、旧档补域与独立终局。约 2–3 次短远征、`T=2R` 等只是设计目标；注入资源的用例不能证明自然收益、返程预算或可滚雪球。本轮不新增贷款、利息、政治、共同项目或全城模拟来掩盖这个未验收面。

## 常驻背包

页脚状态栏「背包」格在战外可点；战中只读，指向下方完整背包视图。完整视图允许查看说明、效果、次数和装备状态，战中使用委托 `RPG.submitBattleAction`，不能另开不耗回合的即时使用路。治疗反馈及 HP 即时刷新统一从 `item:used` 事件处理；卷轴也在该成功提交事件之后重建探索，不能在 `used()` 内提前复制尚未扣次的库存。

`run-l10-checks.py` 复现本地 17 步，保存逐步日志和两把源刀的结果；不是实际 Actions。`verify.mjs` 保留全图、首战、事件、战果、L10／L20 创伤高低检定等旧断言，并调用 `tools/verify-l10-city.mjs`。此无头装配不是宿主存档往返，也不执行 Twee 渲染。第 61 格只核探索段落的 `if` 配对，含合法嵌套／分支与孤立结束／分支的正反小样；它不是任意 Twee 语法解析器。浏览器功能断言曾全过却漏掉页面内宏错误，故浏览器工具另查当前段落的 `.error`／`.error-view`，覆盖段落可见、功能断言、截图三个检查点，并用真实 wiki 的孤立结束标签／合法 if 两态自证。27 个断言组包含此自证及旧田菜单／收获／重复拒绝三组回归；五处建筑的名称、描述另在装配中核对故事 `L10.build()` 模板，不取包内旧 hub。`result.json.pageChecks` 留下每次实际检查的段落与错误节点；次数取该数组长度，不是独立段落数或功能组数。旧冻结头的 67 次由 39 次段落可见、24 次功能、4 次截图检查相加得出，不作为新头固定期望；wiki 正反探针另存自证 JSON。四张截图 JSON 只保存正文／几何，`issues` 在结果的 `pageChecks` 内。检查范围仅为本次访问过的段落，不宣称未访问段落无错。

`e2e-314-l10-city.mjs` 用真实 Chromium、原生鼠标输入和宿主 `Save.slots.save/load` 加 `Engine.show`，核菜单重建、支付、资格、修理、寄存、返程正文、缺域旧档的有田收尾、取消／最终确认、刷新及重开；明确注入资源／工具，不冒充自然远征或平衡验收。Node 22 自带 CDP 所需 `fetch`／`WebSocket`，无需 Playwright 新依赖。`CHROME` 可指定浏览器，`CHROME_DEPS` 指定动态库目录。截图阅读需要浏览器可用的中文字体；也可用私有 `FONTCONFIG_FILE`，不修改故事样式或系统字体。

## 保留的范围边界

- 精英标记只改显示前缀，无无源数值模板；创伤历史从当前持有态反推，不保证记录两次调用间已解除的创伤。
