# 巴别之井 · 试玩版（1–20 层）

这是一个给人玩的东西，不是测试夹具。它会被构建成一个单文件网页，双击就能玩。夹具也就是 e2e 用例在 `tests/e2e/old-house/`，那一份是给 CI 用的，本目录这一份是给试玩者用的。

## 怎么构建

本仓只放故事，引擎按 pin 检出，这是 `books#76` 相 A 的约定。因此构建时要同时给出引擎检出目录。

```bash
# ① 引擎按本仓声明件 `.github/engine-ref.json` 的 ref 检出（唯一权威；✗ 不要用引擎 main）
git clone https://github.com/sagitrs/sgstory /tmp/engine
git -C /tmp/engine checkout "$(jq -r .ref .github/engine-ref.json)"

# ② 构建（★故事目录给**绝对路径**：`build.py` 对相对路径会先拼到**引擎仓根**）
python3 /tmp/engine/build.py "$PWD/stories/babel" --out babel-trial.html

# ③ 装配自检（同一份脚本随故事走 ⇒ 用 `--engine` 指引擎检出目录）
node stories/babel/verify.mjs --engine /tmp/engine
```

产物是 `stories/babel/babel-trial.html` 一个文件。SugarCube 引擎与全部插件及故事脚本都内联其中，没有任何外部依赖，因此可以直接发给别人。

持续集成由 `.github/workflows/babel-tests.yml` 负责，它在 `stories/babel/**` 或 pin 变动时跑上面三步，另加单文件判据、两次构建逐字节相同，以及恒绿门自证。恒绿门自证的做法是把自检的出口注释掉，此时它必须红得了。pin 升级就是改 `.github/engine-ref.json` 的 `ref` 一行，这是一道棘轮，因为引擎漂移会打红故事测试，所以必须显式接受，升版走 PR，并在 `why` 与 `checked` 里记录本次核过什么。

## 怎么玩

用任何现代浏览器双击打开 `babel-trial.html`。目标是从第 1 层爬到第 20 层的城墙。第 10 层到第 11 层的门已经通了，第 20 层到第 21 层的门只画在墙上。

| 步骤 | 在哪做 |
|---|---|
| 1. 苏醒 | 开场，然后选「睁开眼」 |
| 2. 一段爬层 | 在地图视图里逐层向上，从 L1 到 L9，可以采集、遭遇与战斗 |
| 3. 死亡 | 死了会回到第 1 层，此时掉落物品、清空所有效果（包括跨场创伤），体力回满 |
| 4. 一段聚落 | 第 10 层。在营火边整备，用治疗检定处理伤口或直接用掉恢复物；在围栏边开垦与收获 |
| 5. 10 到 11 的单向门 | 第 10 层石门通往第 11 层，回不去，因为段间封闭。本版这一段已经接通 |
| 6. 二段爬层 | 从 L11 到 L19。这里遭遇更硬的东西，包括火甲虫、巨蜂与投弹甲虫，掉落含铁矿 |
| 7. 第 20 层聚落 | 在料场领 6 张锻造图并取木料，然后到锻造台打铁器；在军械堆领盾；在马厩领坐骑 |
| 8. 收尾 | 在第 20 层石门旁看本局读数。20 到 21 的门只定义不挂图，那里是三段的地界 |

状态栏的背包里，道具名是可以点的，这是 C1 与 `#1798` 的内容。能装备的点了就装备或卸下，消耗品点了就用掉一次。

反馈请按 [`PLAYTEST.md`](PLAYTEST.md) 的三栏填写，那个模板是给试玩者直接复制用的。

## 依赖与降级

| 面 | 来源 | 缺席时的表现 |
|---|---|---|
| 地图、单向门与死亡回起点 | core，已合 | 不适用 |
| 采集、建造与收获 | `#1776`，已合 | 不适用 |
| 创伤，也就是跨场 debuff | `#1780`，已合 | 不适用 |
| 遭遇与掉落抽取 | `#1784`（B2） | 桥函数显式报缺并拒绝开战，而不是静默降级。静默会让「遭遇永不发生」看起来像「这层本来就没怪」。`#1863` 把它分成两层：开发者通道（`console.warn`）报出「装配缺口」，并带票号与路径；玩家层只出白话 |

## 已知面（是选择，不是缺陷）

1. **`elite` 只是命名**。遭遇表的 `elite` 标记在本试玩版里表现为敌人名前缀「精英·」，可见即可玩，但不给数值。原因是 SRD 3.5 没有「精英动物」模板，无源的强化会污染 `SPAN1_SCALING` 的 CR 带。
2. **创伤读数精度**。本局「见过的创伤」从持有态反推，因为施加没有独立事件，所以在两次调用之间被施加又被解除的那些会计不到。
3. **第 20 层是终点**。`span2GateExit()` 处理 20 到 21 的出口，它只定义不挂图，因为 `L21` 属三段，候 `#1754` 裁定。因此石门上只有一块告示，图里没有 L21，也没有回边，这一点由自检的第三节断言。
4. **二段没有铁矿采集点**。`iron-ore` 只从二段遭遇的掉落表产出，表在 `climb2.js` 的 L13 至 L19。因此锻造闭环是「打怪取铁，然后图纸，然后铁器」。要加采集点属于内容面，另票处理，本笔不造。
5. **层读面缺席时走命名约定兜底**。`L1` 到 `L9` 的地点 id 就是层 id；整备区也就是 `L10-*`，在两种读法下都判不出层，因此不引入第二套层语义。相关注释见 `src/world/encounters.js`。

## 自检（装配面，不是判定数学）

```bash
python3 build.py && node stories/babel/verify.mjs
```

它把插件与故事脚本装进无头环境，走一遍可玩线并断言十二节。断言的内容包括：地图合法且从 L1 出发全可达；段间封闭，即 10 到 11 接通，20 到 21 只定义不挂图且图里无 L21、无回边；全梯 18 层每层都有采集点与遭遇入口；采集、战斗、死亡回层、建造与收获各自的读数正确；战斗用的是副本，注册面单例不被改写；整备闭环，即掷高治愈、掷低保留；二段遭遇，即好的一侧抽得出、hub 层抽不出、未注册层抛错；创伤，即钝击重击造成骨裂且不被失血遮蔽、跨 `battle:end` 仍在；锻造闭环，即料不够时 rejected 且不扣料、料够时锻造台真出铁器；以及军械与马厩，即盾与坐骑领得到、`when` 前置生效。

判定数学的用例在 `tests/unit/**`，归测试席。本脚本只核装配。
