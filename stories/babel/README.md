# 巴别之井 · 试玩版（1–20 层）

这是**给人玩的东西**，不是测试夹具：把它构建成一个单文件网页，双击就能玩。
夹具（e2e 用例）在 `tests/e2e/old-house/`；那个是给 CI 用的，这个是给**试玩者**用的。

## 怎么构建

**本仓（books）只放故事，引擎按 pin 检出**（`books#76` 相 A）⇒ 构建要同时给出**引擎检出目录**：

```bash
# ① 引擎按本仓声明件 `.github/engine-ref.json` 的 ref 检出（唯一权威；✗ 不要用引擎 main）
git clone https://github.com/sagitrs/sgstory /tmp/engine
git -C /tmp/engine checkout "$(jq -r .ref .github/engine-ref.json)"

# ② 构建（★故事目录给**绝对路径**：`build.py` 对相对路径会先拼到**引擎仓根**）
python3 /tmp/engine/build.py "$PWD/stories/babel" --out babel-trial.html

# ③ 装配自检（同一份脚本随故事走 ⇒ 用 `--engine` 指引擎检出目录）
node stories/babel/verify.mjs --engine /tmp/engine
```

产物是 **`stories/babel/babel-trial.html` 一个文件**（SugarCube 引擎与全部插件/故事脚本都内联，
零外部依赖 ⇒ 可以直接发给别人）。

**CI**：`.github/workflows/babel-tests.yml` 在 `stories/babel/**` 或 pin 变动时跑上面三步
＋ 单文件判据 ＋ 两次构建**逐字节相同** ＋ ★**恒绿门自证**（把自检的出口注释掉，它必须红得了）。
**pin 升级**＝改 `.github/engine-ref.json` 的 `ref` 一行（**棘轮**：引擎漂移打红故事测试＝须显式接受，
升版走 PR），并在 `why`／`checked` 里记本次核过什么。

## 怎么玩

双击打开 `babel-trial.html`（任何现代浏览器）。目标：**从第 1 层爬到第 20 层的城墙**（10→11 的门已通；20→21 的门只画在墙上）。

| 步骤 | 在哪做 |
|---|---|
| 1. 苏醒 | 开场 → 「睁开眼」 |
| 2. 一段爬层 | 地图视图里逐层向上（L1 → L9）：采集、遭遇、战斗 |
| 3. 死亡 | 死了会**回到第 1 层**：掉落、清空所有效果（**包括跨场创伤**）、体力回满 |
| 4. 一段聚落 | 第 10 层：营火边**整备**（治疗检定处理伤口／用掉恢复物）、围栏边**开垦/收获** |
| 5. 10→11 单向门 | 第 10 层石门 → 第 11 层（**回不去**，段间封闭；本版已**接通**）|
| 6. **二段爬层** | L11 → L19：遭遇更硬的东西（火甲虫／巨蜂／投弹甲虫），掉落含**铁矿** |
| 7. **第 20 层聚落** | 料场领**6 张锻造图**＋取木料 ⇒ **锻造台**打铁器；军械堆领**盾**；马厩领**坐骑** |
| 8. 收尾 | 第 20 层石门旁看本局读数（**20→21 的门只定义不挂图** —— 三段的地界） |

**状态栏的背包里，道具名是可以点的**（C1 · `#1798`）：能装备的点了就装备/卸下，消耗品点了就用掉一次。

反馈请按 [`PLAYTEST.md`](PLAYTEST.md) 的三栏填（那个模板是给试玩者直接复制用的）。

## 依赖与降级

| 面 | 来源 | 缺席时的表现 |
|---|---|---|
| 地图/单向门/死亡回起点 | core（已合） | 不适用 |
| 采集/建造/收获 | `#1776`（已合） | 不适用 |
| 创伤（跨场 debuff） | `#1780`（已合） | 不适用 |
| **遭遇/掉落抽取** | **`#1784`（B2）** | 桥函数**显式报出「装配缺口」**并拒绝开战 —— ✗ 静默降级（静默会让「遭遇永不发生」看起来像「这层本来就没怪」） |

## 已知面（✗ 缺陷，是选择）

1. **`elite` 只是命名**：遭遇表的 `elite` 标记在本试玩版表现为敌人名前缀「精英·」（可见即可玩）；
   **不给数值**——SRD 3.5 无「精英动物」模板，无源的强化会污染 `SPAN1_SCALING` 的 CR 带。
2. **创伤读数精度**：本局「见过的创伤」从**持有态**反推（施加没有独立事件）⇒
   两次调用之间被施加又解除的会计不到。
3. **第 20 层是终点**：`span2GateExit()`（20→21）**只定义不挂图**（`L21` 属三段，候 `#1754` 裁）
   ⇒ 石门只有一块告示；图里**没有** L21，也无回边（自检 §③ 断言）。
4. **二段没有铁矿采集点**：`iron-ore` 只从二段遭遇的掉落表出（`climb2.js` 的 L13–L19）⇒
   锻造闭环是「**打怪取铁** ⇒ 图纸 ⇒ 铁器」。要加采集点属内容面（另票），本笔不造。
5. **层读面缺席时走命名约定兜底**：`L1`–`L9` 的地点 id 即层 id；整备区（`L10-*`）在两种读法下都判不出层
   ⇒ 不引入第二套层语义（见 `src/world/encounters.js` 的注释）。

## 自检（装配面，✗ 判定数学）

```bash
python3 build.py && node stories/babel/verify.mjs
```

它把**插件 ＋ 故事脚本**装进无头环境，走一遍可玩线并断言（12 节）：
地图合法且 L1 出发**全可达**、段间封闭（10→11 接通；**20→21 只定义不挂图**、图里无 L21、无回边）、
全梯 18 层每层有采集点与遭遇入口、采集/战斗/死亡回层/建造/收获各自的读数正确、
战斗用的是**副本**（注册面单例不被改写）、**整备闭环**（掷高治愈／掷低保留）、
**二段遭遇**（好的一侧抽得出／hub 层抽不出／未注册层抛错）、**创伤**（钝击重击 ⇒ 骨裂且不被失血遮蔽、
跨 `battle:end` 仍在）、**锻造闭环**（料不够 ⇒ rejected 且**不扣料**；料够 ⇒ 锻造台真出铁器）、
**军械/马厩**（盾与坐骑领得到、`when` 前置生效）。

判定数学的用例在 `tests/unit/**`（归测试席）；本脚本只核**装配**。
