# 数值平衡方法论（`books#201` 乙笔起立；操作者 2026-10-03 指令）

> 一句话：**数值是算出来的，不是拧出来的。** 下面五条定律、一套算式、一张决策表、一份反模式清单 ——
> 每条都附今晚的**真实事故**。判据由跑分器的 `--enforce-target` 自动守（✗ 靠人记得）。

## 零、目标与合同

| 项 | 值 | 判者 |
|---|---|---|
| L9 硬门胜率（带齐乙的保证装备、走温泉） | **0.70–0.85** | `tools/balance-babel.mjs` 的 `--enforce-target`（回归守卫） |
| 未备战（无乙、带伤） | **应被打死**（威胁仍在） | 同上（三格的「不温泉」格即此对照） |
| 温泉的边际 | **不是瓶颈**（加不加温泉不足以翻盘） | 同上（`#185` 的定论底数：+5.0pp） |

## 一、五条定律（每条都有一笔事故）

1. **模型没有复现过一个已知读数之前，它对数值没有发言权。**
   事故：我用**未校准**的模型宣布「达线组合 ⇒ 72.6%」，实跑 **13–20%**。错在我，不在数值。
   ⇒ 校准做法：拿**现状**数值跑模型与跑分器（同一命令、同一 pin），两者须落在同一区间；否则先修模型。
2. **样本量不足不得下决定。** 30 样本的 95% 区间约 **±16pp** ⇒ 连「在不在 0.70–0.85 带内」都判不了。
   事故：我拿 B/C 各 30 样本（13.3% / 23.3% / 16.7%）就判「瓶颈不在 hp/AC」—— 那三个数在噪声里。
   ⇒ 判定用 **N ≥ 200**，并且**看区间**（区间与带比较），✗ 只看点估计。
3. **一次只动一个设计变量，且该变量由设计意图决定。**
   事故：我同一轮里既想加武器又想去改头目血。裁定「方向＝乙」＝**玩家侧保证与去随机化**；
   头目的数值只在其**叙事角色**要求时才动（它是「墙」，不是可随意加减的数字）。
4. **先预测，再验证（验证只跑一次）。** 改之前把预测写进票；跑完对不上 ⇒ **判模型错**，回律一。
   事故：我一次跑三个候选 ⇒ 那已是**扫参**（操作者明确禁止的「硬调数值」）。
5. **账要成对：原值 → 新值 ＋ 期望依据 ＋ 验证读数 ＋ 不变量检查。**
   不变量（每次改动都要过）：①带伤无乙仍会被打死 ②温泉仍不是瓶颈 ③层间阶梯单调（L9 威胁 > L8）
   ④早层读数不回退（其余夹具逐格比对）。

6. **器材必须经过被测物的入口。** 读数面若不在被测对象真正走的那条路上，**任何被测侧的改动都测不到**。
   事故（夜内三种形 + 第四种）：①战斗日志包住故事侧 `R.perform` 而战斗走 `Battle.prototype.perform` ⇒ 回合数读 0、断言**空过**；
   ②**陈旧产物**（换了引擎树却没重烘 `babel-trial.html`）⇒ 四轮结论全部作废；
   ③故事侧 hook（`fight()`／`onEnter`）**跑分器一个都走不到**（三点探针全静默）⇒ 乙保证永远上不了身；
   ④`kill -9` 当验收 ⇒ 不可捕获的信号本就不会跑 trap，险些否定一个**正确**的设计（判据错会把对的判成错的）。
   ⇒ 做法三件：**先探针**（打印入口是否被调用）／**读指纹**（引擎·故事·产物·工具＋命令形状，缺一项不出结论）／**验收判据也要落在真实场景**（CI 的失败早退与 SIGTERM，✗ 不是 SIGKILL）。

## 二、算式（参数全部取自**现码**；引擎口径两条是关键）

```
E[命中]      = (21 − (目标 AC − 攻击加值)) / 20
攻击加值     = 件上有 atkBonus ⇒ 用它；否则 bab ＋ str 加值        ← 引擎口径①（实测：头目 +5 而非 +6）
E[伤害/次]   = (骰面期望 ＋ 加值) × (1 + (21 − critMin)/20)        ← 重击**须确认**；加值含 str
回合预算     = 回合上限 × 每回合我方出手次数                        ← **必须与器材口径一致（律一）**
TTK          = 头目 hp / (E[命中] × E[伤害/次])
TTD_有效     = (玩家 hp ＋ 治疗量×可用次数) / 头目侧同式              ← 治疗＝**用出手换血**，须同时扣回合预算
胜率         = P(回合预算内累计伤害 ≥ 头目 hp) ∧ P(玩家不倒)          ← **分布量，不是均值比**
```

**均值比只能判方向**（玩家/头目 E[伤害/回合] ≥ 1.15 √ 必要条件），**绝对带由跑分器量** ——
这就是 `verify.mjs` ㊴④ 与 `--enforce-target` 的**分工**。

## 三、器材（instrument）要求 —— 读数不可信时，律一无从谈起

1. **回合口径必须被定义并被仪器打印**（`#191`：`--dump-tracks` 逐样本逐回合[行动者/动作/命中/伤害]）。
   事故：我的模型按「玩家 8 次出手」算，实跑约 4 次 ⇒ 差一倍，全部结论作废。
2. **读数须带指纹与命令形状**（引擎 src 摘要｜artifact 路径＋md5｜运行器两件摘要｜node/jsdom｜命令形状｜样本数）。
   事故：同夹具**多夹具跑 26/30 vs 单夹具跑 25/30**（`#191` 顺序依赖）。
3. **多夹具与单夹具必须同值**（`#191` 修好前，任何跨夹具比较都不可用）。

## 四、决策表（样本量与结论）

| 观测 | 判定 |
|---|---|
| N < 200 | **样本不足** —— 不判（✗ 不据此改数） |
| 95% 区间 ⊂ [0.70, 0.85] | 在带内 ⇒ 合入，转 `--enforce-target` 回归守卫 |
| 区间与带相交但未含 | 再取样本（同一命令，✗ 不趁机改数） |
| 区间**完全低于**带 | 按模型找**绑定的那一项**（敏感性在模型内算），预测，再验证一次 |
| 区间**完全高于**带 | 同上，方向相反；同时检查**不变量①**（威胁是否被抹平） |

## 五、反模式（禁止清单，各附今晚事故）

| 反模式 | 事故 |
|---|---|
| 扫参试凑（「改一下看看」） | 我一次跑 hp/AC 两候选 ＋ 想再改武器 |
| 小样本下结论 | 30 样本判「瓶颈不在 hp/AC」 |
| 未校准的模型拿来定数 | 「72.6%」 vs 实测 13–20% |
| 一轮动两侧（玩家＋头目） | 我首版同笔既加武器又降头目伤害 |
| 把「能过」当作唯一目标（抹平威胁） | 不变量①就是防这个 |
| 用没定义单位的读数 | 回合口径不明时的一切比较 |

## 六、流程（一次完整走法）

`票（期望算式＋明账骨架）` → **校准**（现状：模型 vs 跑分器同区间）→ **敏感性在模型内**（找出绑定项）
→ **选一个设计变量**（由设计意图定）→ **写预测** → **验证一次（N ≥ 200，带指纹与命令形状）**
→ 过不变量四项 → 合入 ⇒ `--enforce-target` 转为**回归守卫**（此后漂移自动红）。
